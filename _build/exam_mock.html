Θέμα 1 · Prolog (35 μονάδες)

Μπορείτε να χρησιμοποιήσετε συνήθη ενσωματωμένα κατηγορήματα της Prolog.

(α) best_paid/2 10/100

Δίνονται γεγονότα salary(Όνομα, Τμήμα, Μισθός). Συμπληρώστε τον ορισμό

best_paid(Dept, Name) :- salary(.............), .........................

ώστε, για κάθε τμήμα, να επιστρέφει τον υπάλληλο με τον μεγαλύτερο μισθό στο τμήμα του. Αν υπάρχουν ισόπαλοι, να επιστρέφονται όλοι μέσω οπισθοδρόμησης. Δεν επιτρέπεται να ορίσετε άλλα κατηγορήματα ή άλλη πρόταση.

salary(ann, sales, 1800). salary(bob, it, 2400). salary(cat, sales, 2100). salary(dan, it, 2400). salary(eve, hr, 1500). salary(fay, sales, 2100). salary(gus, hr, 1500). salary(hal, it, 1900). salary(ivy, hr, 1400). ?- best_paid(Dept, Name). Dept = it, Name = bob --> ; Dept = sales, Name = cat --> ; Dept = it, Name = dan --> ; Dept = hr, Name = eve --> ; Dept = sales, Name = fay --> ; Dept = hr, Name = gus --> ; No
✅ Λύση (α)
salary(ann, sales, 1800). salary(bob, it, 2400). salary(cat, sales, 2100). salary(dan, it, 2400). salary(eve, hr, 1500). salary(fay, sales, 2100). salary(gus, hr, 1500). salary(hal, it, 1900). salary(ivy, hr, 1400). % ο πιο καλοπληρωμένος κάθε τμήματος (όλοι οι ισόπαλοι), μόνο αυτή η πρόταση best_paid(Dept, Name) :- salary(Name, Dept, S), \+ ( salary(_, Dept, S2), S2 > S ).

Το μοτίβο «βέλτιστο με \+» με έναν περιορισμό: ο εσωτερικός generator κρατά το ίδιο Dept, οπότε η σύγκριση γίνεται μόνο μέσα στο τμήμα. Αν γράψεις salary(_, _, S2), βγαίνουν μόνο οι bob και dan (το μέγιστο όλης της εταιρείας).

(β) repeats/2 25/100

i. (10/100) Ορίστε το κατηγόρημα repeats(Pattern, List), το οποίο επιτυγχάνει όταν η List αποτελείται από μία ή περισσότερες συνεχόμενες επαναλήψεις της μη κενής λίστας Pattern, με στοιχεία ακριβώς ίδια με αυτά της Pattern.

?- repeats([a, f(X)], [a, f(X), a, f(X)]). Yes ?- repeats([a, f(X)], [a, f(X), a, f(Y)]). No ?- repeats([g(X), Y], [g(1), 2, g(1), 2]). No ?- repeats([a, b], [a, b, a]). No ?- repeats([h(X)], [h(1), h(2)]). No

ii. (5/100) Αν η απαίτηση ήταν τα στοιχεία να είναι ενοποιήσιμα, ποια ελάχιστη αλλαγή θα κάνατε στην υλοποίηση του (i); Στην παραλλαγή αυτή όλες οι ερωτήσεις εκτός από την 4η πρέπει να απαντούν Yes.

iii. (5/100) Αν στη θέση του ελέγχου ταυτότητας γράφατε σκέτο =, τι θα απαντούσαν οι πέντε ερωτήσεις; Αιτιολογήστε.

iv. (5/100) Γράψτε το repeats/2 του (i) σε μία πρόταση, χρησιμοποιώντας μόνο το append/3 και το ==.

Έλεγχος μετά τον χρόνο

✅ Λύση (β)i
% repeats(Pattern, List): η List είναι μία ή περισσότερες επαναλήψεις της Pattern (μη κενή) repeats(P, L) :- same(P, L, Rest), ( Rest == [] ; repeats(P, Rest) ). % same(P, L, Rest): η L ξεκινά με τα στοιχεία της P (ακριβώς ίδια), Rest ό,τι περισσεύει same([], Rest, Rest). same([X|Xs], [Y|Ys], Rest) :- X == Y, same(Xs, Ys, Rest).

Το same/3 «καταναλώνει» ένα αντίγραφο του μοτίβου από την αρχή της λίστας και επιστρέφει ό,τι περισσεύει. Αν δεν περισσεύει τίποτα, τέλος· αλλιώς το υπόλοιπο πρέπει να είναι πάλι επαναλήψεις. Το == ελέγχει ταυτότητα χωρίς να δεσμεύει.

✅ Λύση (β)ii
% άλλαξε μόνο τη σύγκριση, ώστε όλες οι ερωτήσεις εκτός της 4ης να απαντούν Yes repeats(P, L) :- same(P, L, Rest), ( Rest == [] ; repeats(P, Rest) ). % same(P, L, Rest): η L ξεκινά με τα στοιχεία της P (ακριβώς ίδια), Rest ό,τι περισσεύει same([], Rest, Rest). same([X|Xs], [Y|Ys], Rest) :- \+ X \= Y, same(Xs, Ys, Rest).

Το \+ X \= Y ελέγχει κάθε ζεύγος χωριστά και δεν κρατά δεσμεύσεις, οπότε το h(X) ταιριάζει και με το h(1) και με το h(2). Η 4η ερώτηση μένει No λόγω μήκους.

✅ Λύση (β)iii
ΕρώτησηΜε σκέτο =Γιατί
1Yesτα στοιχεία είναι ήδη ίδια
2Yes, X = Yτο f(X) = f(Y) δένει X με Y
3Yes, X = 1, Y = 2το πρώτο αντίγραφο δένει τις μεταβλητές, το δεύτερο ταιριάζει
4Noπερισσεύει το a
5Noτο h(X) = h(1) δένει X = 1, και μετά h(1) = h(2) αποτυγχάνει

Είναι το ίδιο φαινόμενο με το (β)ii του Ιουνίου: οι δεσμεύσεις του ενός ζεύγους μεταφέρονται στα επόμενα.

✅ Λύση (β)iv
% ίδια σημασία με το (i), μία πρόταση, μόνο append/3 και == repeats(P, L) :- append(P1, Rest, L), P1 == P, ( Rest == [] ; repeats(P, Rest) ).

Το append(P1, Rest, L) δοκιμάζει κάθε πρόθεμα της λίστας· μόνο αυτό που είναι ίδιο με το μοτίβο περνά το ==. Το μοτίβο είναι μη κενό, άρα η αναδρομή δουλεύει σε μικρότερη λίστα.

Θέμα 2 · Μοντελοποίηση (20 μονάδες)

Σε ένα τμήμα, N φοιτητές πρέπει να αναλάβουν διπλωματική με έναν από K επιβλέποντες. Ο φοιτητής s έχει δηλώσει σύνολο αποδεκτών επιβλεπόντων As και, για κάθε k ∈ As, τη θέση προτίμησης rsk (1 = πρώτη επιλογή). Κάθε φοιτητής ανατίθεται σε ακριβώς έναν αποδεκτό επιβλέποντα, και ο επιβλέπων k αναλαμβάνει το πολύ Ck φοιτητές.

Θέμα 3 · Σημασιολογία (25 μονάδες)

Δίνεται το λογικό πρόγραμμα P:

p(a, b). p(f(X), Y) :- p(X, Y). q(X) :- p(X, X).
  1. (5/100) Ποιο είναι το σύμπαν Herbrand UL και ποια η βάση Herbrand BL; Είναι η BL μοντέλο του προγράμματος; Αιτιολογήστε.
  2. (5/100) Ποιο είναι το ελάχιστο μοντέλο MP;
  3. (10/100) Μπορεί το A = { p(b, b) } να είναι υποσύνολο κάποιου μοντέλου; Αν ναι, και MA η τομή όλων των μοντέλων που περιέχουν το A, με τι ισούται το BL − MA;
  4. (5/100) Υπάρχει SLD-απόρριψη για τον στόχο ?- p(f(f(a)), b), q(b).; Για τον ?- p(f(a), b), p(a, b).; Αιτιολογήστε χωρίς να κατασκευάσετε απόρριψη.
✅ Λύση Θέματος 3
(α) UL = {a, b, f(a), f(b), f(f(a)), f(f(b)), …} = { fn(a), fn(b) : n ≥ 0 }
BL = { p(s, t) : s, t ∈ UL } ∪ { q(t) : t ∈ UL }
Η BL είναι μοντέλο: σε κάθε βασικό στιγμιότυπο κάθε πρότασης η κεφαλή ανήκει στη BL, άρα η πρόταση αληθεύει. Αυτό ισχύει για κάθε οριστικό πρόγραμμα.

(β) TP↑1 = { p(a, b) } · TP↑2 = { p(a, b), p(f(a), b) } · …
MP = TP↑ω = { p(fn(a), b) : n ≥ 0 }
Κανένα q: το q(t) θέλει p(t, t), και στο MP το δεύτερο όρισμα είναι πάντα b ενώ το πρώτο δεν είναι ποτέ b.

(γ) Ναι (π.χ. η BL είναι μοντέλο που το περιέχει). MA = ελάχιστο μοντέλο του P ∪ { p(b, b). }:
MA = { p(t, b) : t ∈ UL } ∪ { q(b) }  // p(fn(b), b) από την αναδρομική πρόταση, q(b) από το p(b, b)
BL − MA = { p(s, t) : s, t ∈ UL, t ≠ b } ∪ { q(t) : t ∈ UL, t ≠ b }

(δ) Πρώτος στόχος: το q(b) ∉ MP, άρα δεν υπάρχει SLD-απόρριψη (ορθότητα: μια απόρριψη θα έκανε το q(b) λογική συνέπεια του P, δηλαδή στοιχείο του MP).
Δεύτερος στόχος: p(f(a), b), p(a, b) ∈ MP, άρα υπάρχει SLD-απόρριψη (πληρότητα της SLD-επίλυσης).

Οι απαντήσεις του (β) έως (δ) ελέγχθηκαν σε SWI-Prolog με ερωτήσεις στα αντίστοιχα προγράμματα.

Θέμα 4 · Αναπαράσταση γνώσης (20 μονάδες)

(α) (5/100) Τι σημαίνει ότι η οπίσθια συλλογιστική είναι «οδηγούμενη από τον στόχο» και η εμπρόσθια «οδηγούμενη από τα δεδομένα»; Δώστε κριτήρια για την επιλογή ανάμεσά τους.

(β) (15/100) Στη βάση γνώσης του editor οι κανόνες είναι if … then … με προϋποθέσεις που μπορεί να περιέχουν and και or. Συμπληρώστε το is_true/2 ώστε το δεύτερο όρισμα να επιστρέφει το δέντρο απόδειξης (απάντηση σε ερώτηση «πώς»): για γεγονός P η απόδειξη είναι το P· για συμπέρασμα κανόνα είναι P <= Απόδειξη_Προϋπόθεσης· για σύζευξη Απόδειξη1 and Απόδειξη2· για διάζευξη η απόδειξη του μέλους που αληθεύει.

?- is_true(call_dealer, Proof). Proof = call_dealer <= (engine_wont_start <= (battery_dead <= lights_dim and engine_cranks_slowly)) and car_is_new
✅ Λύση (α)

Ενδεικτική απάντηση: η οπίσθια συλλογιστική ξεκινά από τον στόχο και ψάχνει κανόνες που τον συμπεραίνουν, ζητώντας δεδομένα μόνο όταν χρειάζονται (goal driven). Η εμπρόσθια ξεκινά από τα γνωστά γεγονότα και εφαρμόζει κανόνες μέχρι να μην προκύπτει τίποτα νέο (data driven). Κριτήρια: αν θέλουμε να αποδείξουμε κάτι συγκεκριμένο ή απλώς να δούμε τι προκύπτει· αν έχουμε όλα τα δεδομένα από την αρχή· αν ο AND-OR γράφος έχει λίγους τελικούς και πολλούς αρχικούς κόμβους ή το αντίστροφο· τι υποστηρίζει το κέλυφος που θα χρησιμοποιηθεί.

✅ Λύση (β)
% Θέμα 4 (β): οπίσθια συλλογιστική που επιστρέφει και το «πώς» :- op(800, fx, if). :- op(700, xfx, then). :- op(300, xfy, or). :- op(200, xfy, and). :- op(800, xfx, <=). if battery_dead or no_fuel then engine_wont_start. if lights_dim and engine_cranks_slowly then battery_dead. if fuel_gauge_empty then no_fuel. if engine_wont_start and car_is_new then call_dealer. fact(lights_dim). fact(engine_cranks_slowly). fact(car_is_new). % is_true(P, Proof): Proof = P αν είναι γεγονός, P <= ΑπόδειξηΠροϋπόθεσης αν βγήκε από κανόνα is_true(P, P) :- fact(P). is_true(P, P <= CondProof) :- if Cond then P, is_true(Cond, CondProof). is_true(P1 and P2, Proof1 and Proof2) :- is_true(P1, Proof1), is_true(P2, Proof2). is_true(P1 or P2, Proof) :- is_true(P1, Proof) ; is_true(P2, Proof).

Είναι ο μετα-διερμηνέας των σημειώσεων για τις εξηγήσεις «πώς». Κάθε πρόταση του is_true/2 χτίζει στο δεύτερο όρισμα το κομμάτι της απόδειξης που αντιστοιχεί στη μορφή του στόχου.
