1. Ταξινόμηση Λιστών

Η ταξινόμηση είναι το "Hello World" κάθε δομής δεδομένων. Στην Prolog θα δούμε τρεις κλασικές μεθόδους που χρησιμοποιούν διαφορετικές αναδρομικές στρατηγικές, και θα συγκρίνουμε την αποδοτικότητά τους.

📝 Προαπαιτούμενο: το κατηγόρημα gt/2

Όλοι οι αλγόριθμοι θεωρούν ότι έχουμε ορίσει μια σχέση διάταξης. Για αριθμούς:

gt(X, Y) :- X > Y.

Με αυτό τον τρόπο μπορούμε εύκολα να γενικεύσουμε τους αλγορίθμους για ταξινόμηση συμβολοσειρών, ζευγών, ή οποιουδήποτε τύπου, αρκεί να ορίσουμε το αντίστοιχο gt.

1.1 Μέθοδος Φυσαλίδας (Bubblesort)

Ιδέα: Βρες δύο διαδοχικά στοιχεία σε λάθος διάταξη, αντιμετάθεσέ τα, και επανέλαβε μέχρι να μην υπάρχει τέτοιο ζευγάρι.

bubblesort(List, Sorted) :- swap(List, List1), % βρες ζευγάρι για ανταλλαγή !, % αν βρήκες, δέσμευσε bubblesort(List1, Sorted). % και ξαναπροσπάθησε bubblesort(Sorted, Sorted). % αν δεν υπάρχει swap, τελείωσε swap([X, Y|Rest], [Y, X|Rest]) :- gt(X, Y). % αντιμετάθεσε αν X > Y swap([Z|Rest], [Z|Rest1]) :- swap(Rest, Rest1). % αλλιώς ψάξε στην ουρά
bubblesort(List, Sorted) :-
Πρώτη πρόταση: η αναδρομική περίπτωση.
swap(List, List1),
Καλούμε το swap να βρει το πρώτο ζευγάρι παράταξης που είναι σε λάθος σειρά. Επιστρέφει νέα λίστα List1 με την ανταλλαγή πραγματοποιημένη.
!,
Πράσινο cut: αν το swap πέτυχε, δεν θέλουμε να επιστρέψει η Prolog εδώ και να δοκιμάσει τη δεύτερη πρόταση. Χωρίς το cut, η Prolog θα επέτρεπε λάθος συμπεριφορά κατά την οπισθοδρόμηση.
bubblesort(List1, Sorted).
Αναδρομική κλήση στη νέα λίστα.
bubblesort(Sorted, Sorted).
Βασική περίπτωση: αν δεν βρέθηκε ζευγάρι (το swap απέτυχε), τότε η λίστα είναι ήδη ταξινομημένη.

Το swap/2 πετυχαίνει αν υπάρχει τουλάχιστον ένα ζεύγος σε λάθος διάταξη, και επιστρέφει τη λίστα με αυτό το ζεύγος ανταλλαγμένο:

Αρχικά: 53814
Πέρασμα 1: 35814 → βρήκαμε 5>3, swap
Πέρασμα 2: 35184 → 8>1, swap
...συνεχίζει → 13458
⚠️ Πολυπλοκότητα

Στη χειρότερη περίπτωση: O(n²). Για μεγάλες λίστες είναι πολύ αργό. Χρησιμοποιείται κυρίως διδακτικά.

1.2 Μέθοδος Εισαγωγής (Insertsort)

Ιδέα: Ταξινόμησε την ουρά της λίστας, και μετά εισήγαγε την κεφαλή στην κατάλληλη θέση.

insertsort([], []). insertsort([X|Tail], Sorted) :- insertsort(Tail, SortedTail), % αναδρομικά ταξινόμησε την ουρά insert(X, SortedTail, Sorted). % και εισήγαγε την κεφαλή insert(X, [Y|Sorted], [Y|Sorted1]) :- gt(X, Y), % αν X > Y, X πάει αργότερα !, insert(X, Sorted, Sorted1). insert(X, Sorted, [X|Sorted]). % αλλιώς X πάει μπροστά
💡 Πώς διαβάζεται το insert/3

insert(X, ΕισέρχεταιΣτη, ΠαράγεταιΗ). Το X "ταξιδεύει" κατά μήκος της ταξινομημένης λίστας μέχρι να βρει στοιχείο όχι μικρότερο από αυτό — τότε σταματάει και τοποθετείται εκεί.

Πάλι O(n²) στη χειρότερη — αν η λίστα είναι εντελώς ανάποδα ταξινομημένη.

1.3 Γρήγορη Μέθοδος (Quicksort)

Ιδέα (Divide & Conquer): Διάλεξε ένα στοιχείο "οδηγό" (pivot — εδώ απλώς η κεφαλή της λίστας). Χώρισε τα υπόλοιπα σε δύο λίστες: μικρότερα και μεγαλύτερα. Ταξινόμησε τις δύο λίστες αναδρομικά. Συνένωσε τις με τον οδηγό στη μέση.

quicksort([], []). quicksort([X|Tail], Sorted) :- split(X, Tail, Small, Big), % χώρισε γύρω από το X quicksort(Small, SortedSmall), % ταξινόμησε το μικρό μέρος quicksort(Big, SortedBig), % ταξινόμησε το μεγάλο μέρος append(SortedSmall, [X|SortedBig], Sorted). % ενώσε split(_, [], [], []). split(X, [Y|Tail], [Y|Small], Big) :- gt(X, Y), !, % Y < X → small split(X, Tail, Small, Big). split(X, [Y|Tail], Small, [Y|Big]) :- split(X, Tail, Small, Big). % αλλιώς → big

Οπτικά για τη λίστα [5,3,7,8,1,4,7,6]:

53781476 οδηγός: 5
↓ split
< 5
314 5 ≥ 5
7876
↓ recurse on each
134 5 6778
↓ append με 5 στη μέση
13456778
💡 Πολυπλοκότητα Quicksort

Μέση περίπτωση: O(n log n) — πολύ καλύτερη από bubble/insert. Χειρότερη περίπτωση: O(n²) (συμβαίνει αν η λίστα είναι ήδη ταξινομημένη και ο οδηγός πέφτει στο ένα άκρο).

⚠️ Το append κοστίζει

Σε κάθε βήμα της quicksort καλούμε append, που είναι O(k). Με λίστες διαφορών (Κεφάλαιο 2) μπορούμε να το κάνουμε O(1), οδηγώντας σε πιο αποδοτική quicksort2.

1.4 Συγχώνευση Ταξινομημένων Λιστών (Merge)

Δίνονται δύο ήδη ταξινομημένες λίστες, παράγουμε μια ταξινομημένη συνένωση:

merge([], List, List) :- !. merge(List, [], List) :- !. merge([X|Rest1], [Y|Rest2], [X|Rest3]) :- X < Y, !, merge(Rest1, [Y|Rest2], Rest3). merge(List1, [Y|Rest2], [Y|Rest3]) :- merge(List1, Rest2, Rest3).

Ερώτηση:

?- merge([2,4,7], [1,3,4,8], X). X = [1, 2, 3, 4, 4, 7, 8]

Με βάση τη συγχώνευση μπορούμε να φτιάξουμε τη mergesort: χώρισε στα δύο, ταξινόμησε καθένα, συγχώνευσε. Άσκηση εξετάσεων!

2. Δυαδικά Δέντρα (Binary Trees)

Ένα δυαδικό δέντρο είναι μια αναδρομική δομή: είτε είναι κενό, είτε αποτελείται από μια ρίζα και δύο υποδέντρα (αριστερό και δεξί).

2.1 Αναπαράσταση στην Prolog

Χρησιμοποιούμε δύο σύμβολα:

  • nil για το κενό δέντρο
  • t(Left, Root, Right) για μη κενό δέντρο με ρίζα Root και υποδέντρα Left, Right

Παράδειγμα:

T = t(t(nil, b, nil), a, t(t(nil, d, nil), c, nil))
📝 Γιατί χρειαζόμαστε δύο σύμβολα;

Για να μπορεί το pattern matching να ξεχωρίσει "κενό" από "μη κενό". Η Prolog ενοποιεί το t(L, X, R) μόνο με μη κενό δέντρο, ενώ το nil μόνο με κενό. Αυτό μας επιτρέπει να γράφουμε καθαρές αναδρομές με δύο περιπτώσεις βάσης.

2.2 Στοιχείο μέλος δέντρου: in/2

Αν δεν υπάρχει διάταξη, πρέπει να ψάξουμε όλους τους κόμβους:

in(X, t(_, X, _)). % (α) είναι η ρίζα in(X, t(L, _, _)) :- % (β) ή είναι στο αριστερό in(X, L). in(X, t(_, _, R)) :- % (γ) ή είναι στο δεξί in(X, R).

Με αυτό μπορούμε να ψάξουμε ένα στοιχείο ή να αριθμήσουμε όλα τα στοιχεία (μη ντετερμινιστικά):

?- in(X, t(t(nil, b, nil), a, t(t(nil, d, nil), c, nil))). X = a -> ; X = b -> ; X = c -> ; X = d -> ; no
⚠️ Πολυπλοκότητα

Στη χειρότερη περίπτωση O(n) γιατί ψάχνουμε όλο το δέντρο. Αν θέλουμε O(log n), χρειαζόμαστε δυαδικά λεξικά (BST) — επόμενη ενότητα.

2.3 Συνηθισμένες Ασκήσεις

📚 Άσκηση 1: binarytree/1

Ορίστε κατηγόρημα που πετυχαίνει αν το όρισμά του είναι έγκυρο δυαδικό δέντρο:

binarytree(nil). binarytree(t(L, _, R)) :- binarytree(L), binarytree(R).
📚 Άσκηση 2: height/2 (ύψος δέντρου)
height(nil, 0). height(t(L, _, R), H) :- height(L, HL), height(R, HR), max(HL, HR, HM), H is HM + 1. max(A, B, A) :- A >= B, !. max(_, B, B).
📚 Άσκηση 3: linearize/2 (συλλογή στοιχείων σε λίστα)
linearize(nil, []). linearize(t(L, X, R), List) :- linearize(L, LL), linearize(R, RL), append(LL, [X|RL], List).

Παράγει την ενδοδιατεταγμένη (in-order) διέλευση. Αν αλλάξεις τη σειρά των append, παίρνεις pre-order ή post-order.

3. Δυαδικά Λεξικά (BST)

Ένα Δυαδικό Λεξικό (Binary Dictionary) ή Δέντρο Αναζήτησης (BST) είναι δυαδικό δέντρο με μια επιπλέον ιδιότητα διάταξης.

🧠 Η Ιδιότητα BST (αρχή της διάταξης)

Για κάθε κόμβο t(Left, Root, Right):

  • Όλα τα στοιχεία του Left είναι μικρότερα του Root
  • Όλα τα στοιχεία του Right είναι μεγαλύτερα του Root
  • Τα υποδέντρα Left και Right είναι κι αυτά BSTs

Πρόσεξε ότι κάθε στοιχείο στο δεξί υποδέντρο του 5 είναι > 5, και κάθε στοιχείο στο αριστερό < 5. Το ίδιο ισχύει για κάθε κόμβο!

3.1 Αναζήτηση: in/2

Αυτή τη φορά εκμεταλλευόμαστε τη διάταξη για να ψάχνουμε μόνο ένα υποδέντρο:

in(X, t(_, X, _)). in(X, t(Left, Root, _)) :- gt(Root, X), % Root > X → αριστερά in(X, Left). in(X, t(_, Root, Right)) :- gt(X, Root), % X > Root → δεξιά in(X, Right).
💡 Γιατί είναι O(log n);

Σε κάθε βήμα αποκλείουμε το μισό δέντρο. Σε ισορροπημένο BST με n στοιχεία, η αναζήτηση χρειάζεται log₂(n) βήματα. Προσοχή: σε ένα δέντρο που είναι "καμωμένο σαν λίστα" (όλα στο ένα πλάι), η αναζήτηση γίνεται πάλι O(n).

3.2 Εισαγωγή σε Φύλλο: addleaf/3

Η απλούστερη μέθοδος εισαγωγής. Κατεβαίνουμε στο δέντρο σύμφωνα με τη διάταξη μέχρι να βρούμε ένα nil, και αντικαθιστούμε το nil με το νέο φύλλο.

addleaf(nil, X, t(nil, X, nil)). % στο κενό, φύτεψε φύλλο addleaf(t(L, X, R), X, t(L, X, R)). % ήδη υπάρχει — μην το ξανά-εισάγεις addleaf(t(L, Root, R), X, t(L1, Root, R)) :- gt(Root, X), addleaf(L, X, L1). % πήγαινε αριστερά addleaf(t(L, Root, R), X, t(L, Root, R1)) :- gt(X, Root), addleaf(R, X, R1). % πήγαινε δεξιά

Παράδειγμα διαδοχικών εισαγωγών:

?- addleaf(t(t(nil,3,nil), 5, t(nil,8,nil)), 6, D2), addleaf(D2, 7, D3), addleaf(D3, 4, D4).

Αυτό παράγει διαδοχικά τα δέντρα D1, D2, D3, D4:

D1 (αρχικό)
D2 (+6)
D3 (+7)
D4 (+4)

3.3 Διαγραφή Κόμβου: del/3 και delmin/3

Η διαγραφή είναι πιο δύσκολη γιατί έχουμε τρεις περιπτώσεις:

  1. Ο κόμβος προς διαγραφή δεν έχει αριστερό παιδί → ο δεξιός γίνεται αντικαταστάτης
  2. Δεν έχει δεξί παιδί → ο αριστερός γίνεται αντικαταστάτης
  3. Έχει και τα δύο παιδιά → αντικατέστησέ τον με το ελάχιστο του δεξιού υποδέντρου (αυτό διατηρεί την ιδιότητα BST)
% Περίπτωση 1: ρίζα = X, δεν έχει αριστερό del(t(nil, X, Right), X, Right). % Περίπτωση 2: ρίζα = X, δεν έχει δεξί del(t(Left, X, nil), X, Left). % Περίπτωση 3: ρίζα = X, έχει και τα δύο παιδιά del(t(Left, X, Right), X, t(Left, Y, Right1)) :- delmin(Right, Y, Right1). % πάρε min από δεξιά % Περιπτώσεις 4-5: ρίζα ≠ X — κατέβα αριστερά ή δεξιά del(t(Left, Root, Right), X, t(Left1, Root, Right)) :- gt(Root, X), del(Left, X, Left1). del(t(Left, Root, Right), X, t(Left, Root, Right1)) :- gt(X, Root), del(Right, X, Right1). % delmin: βρες & αφαίρεσε το ελάχιστο στοιχείο delmin(t(nil, Y, Right), Y, Right). delmin(t(Left, Root, Right), Y, t(Left1, Root, Right)) :- delmin(Left, Y, Left1). % πάντα αριστερά μέχρι nil
💡 Γιατί ελάχιστο δεξιού (ή μέγιστο αριστερού);

Είναι ο μοναδικός τρόπος να επιλέξεις αντικαταστάτη που να διατηρεί τη διάταξη BST. Το ελάχιστο του δεξιού είναι το αμέσως μεγαλύτερο στοιχείο από αυτό που αφαιρούμε, και έτσι όλα τα στοιχεία στα αριστερά παραμένουν μικρότερα και όλα στα δεξιά (εκτός αυτού) παραμένουν μεγαλύτερα.

3.4 Εισαγωγή στη Ρίζα: addroot/3

Πιο σύνθετη μέθοδος: εισάγει το νέο στοιχείο ως νέα ρίζα, αναδιοργανώνοντας το δέντρο. Αυτό είναι χρήσιμο σε περιπτώσεις όπου τα νέα στοιχεία είναι πιθανότερο να ζητηθούν σύντομα (τοπικότητα).

addroot(nil, X, t(nil, X, nil)). addroot(t(L, Y, R), X, t(L1, X, t(L2, Y, R))) :- gt(Y, X), addroot(L, X, t(L1, X, L2)). addroot(t(L, Y, R), X, t(t(L, Y, R1), X, R2)) :- gt(X, Y), addroot(R, X, t(R1, X, R2)).

3.5 Μη-ντετερμινιστική Εισαγωγή: add/3

Το add/3 δεν δεσμεύεται από πού θα μπει το στοιχείο. Συνδυάζει addroot και αναδρομική κατάβαση:

add(Tree, X, NewTree) :- addroot(Tree, X, NewTree). add(t(L, Y, R), X, t(L1, Y, R)) :- gt(Y, X), add(L, X, L1). add(t(L, Y, R), X, t(L, Y, R1)) :- gt(X, Y), add(R, X, R1).
⚠️ Μη ντετερμινιστικό!

Με backtracking, το add μπορεί να επιστρέψει πολλά διαφορετικά δέντρα, όλα τα οποία ικανοποιούν την ιδιότητα BST. Χρήσιμο για άσκηση κατανόησης πολλαπλών λύσεων!

4. Γράφοι (Graphs)

Ένας γράφος αποτελείται από κορυφές (vertices/nodes) και ακμές (edges) που τις συνδέουν. Είναι θεμελιώδης δομή για χάρτες, δίκτυα, μηχανισμούς και πολλά CSPs.

4.1 Τρόποι Αναπαράστασης

Υπάρχουν 3 κύριες αναπαραστάσεις στην Prolog. Ας δούμε τον γράφο με κορυφές {a,b,c,d} και ακμές a-b, b-c, b-d, c-d:

1. Σύνολο Γεγονότων
connected(a, b). connected(b, c). connected(b, d). connected(c, d).

✓ Φυσικό για στατικούς γράφους
✗ Δύσκολο να μεταβιβαστεί

2. Δομή graph/2
G1 = graph( [a,b,c,d], [e(a,b), e(b,d), e(b,c), e(c,d)])

✓ Διευκολύνει μεταβίβαση
✓ Επιτρέπει συλλογή κόμβων

3. Λίστες Γειτνίασης
G1 = [ a->[b], b->[a,c,d], c->[b,d], d->[b,c] ]

✓ Γρήγορη πρόσβαση γειτόνων

Για κατευθυνόμενο γράφο με κόστος στις ακμές:

G2 = graph([s, t, u, v], [e(s, t, 3), e(t, v, 1), e(t, u, 5), e(u, t, 2), e(v, u, 2)])

4.2 Εύρεση Μονοπατιού: path/4

Θέλουμε ένα μονοπάτι από κορυφή A σε κορυφή Z, χωρίς κύκλους.

path(A, Z, Graph, Path) :- path1(A, [Z], Graph, Path). % Σταμάτα όταν φτάσουμε στο A: η λίστα παραγωγής αρχίζει από A path1(A, [A|Path1], _, [A|Path1]) :- node(A, Graph). % Διαφορετικά, βρες γείτονα X του τρέχοντος Y, μη επισκεφθέντα path1(A, [Y|Path1], Graph, Path) :- adjacent(X, Y, Graph), not member(X, Path1), path1(A, [X, Y|Path1], Graph, Path). adjacent(X, Y, graph(_, Edges)) :- member(e(X, Y), Edges) ; member(e(Y, X), Edges).
⚠️ Γιατί η λίστα Path1 κρατά τα ήδη επισκεφθέντα;

Αν δεν την κρατούσαμε, η αναζήτηση θα μπορούσε να μπει σε άπειρο βρόχο πηγαίνοντας a→b→a→b→... Ο έλεγχος not member(X, Path1) αποτρέπει αυτή την περιττή επανεπίσκεψη.

4.3 Μονοπάτι Hamilton

Ένα μονοπάτι Hamilton επισκέπτεται κάθε κορυφή ακριβώς μία φορά. Στην Prolog το ορίζουμε ως απλό μονοπάτι που καλύπτει όλες τις κορυφές:

hamiltonian(Graph, Path) :- path(_, _, Graph, Path), % οποιοδήποτε μονοπάτι covers(Path, Graph). % που καλύπτει όλους τους κόμβους covers(Path, Graph) :- not (node(N, Graph), not member(N, Path)). node(N, graph(Nodes, _)) :- member(N, Nodes).
🧠 Διαβάζοντας το covers

"Δεν υπάρχει κόμβος N που να μην είναι μέλος του Path". Διπλή άρνηση = κάθε κόμβος είναι μέλος. Αυτό είναι το άπειρο της Prolog: ορίζω το θετικό με δύο αρνητικά.

4.4 Μονοπάτι με Κόστος: path/5

Επεκτείνουμε το path/4 ώστε να συσσωρεύει το συνολικό κόστος:

path(A, Z, Graph, Path, Cost) :- path1(A, [Z], 0, Graph, Path, Cost). path1(A, [A|Path1], Cost1, _, [A|Path1], Cost1) :- node(A, Graph). path1(A, [Y|Path1], Cost1, Graph, Path, Cost) :- adjacent(X, Y, CostXY, Graph), not member(X, Path1), Cost2 is Cost1 + CostXY, path1(A, [X, Y|Path1], Cost2, Graph, Path, Cost). adjacent(X, Y, CostXY, graph(_, Edges)) :- member(e(X, Y, CostXY), Edges) ; member(e(Y, X, CostXY), Edges).

4.5 Συντομότερο/Μακρύτερο Μονοπάτι

Με το path/5 και χρήση άρνησης ως αποτυχίας μπορούμε να βρούμε το συντομότερο μονοπάτι:

% Μονοπάτι ελαχίστου κόστους από node1 σε node2 ?- path(node1, node2, Graph, MinPath, MinCost), not (path(node1, node2, Graph, _, Cost), Cost < MinCost).
💡 Πώς δουλεύει

"Δώσε μου ένα μονοπάτι, και βεβαιώσου ότι δεν υπάρχει άλλο με μικρότερο κόστος". Η Prolog θα δοκιμάσει κάθε δυνατό μονοπάτι μέσω backtracking μέχρι να βρει αυτό που ικανοποιεί τη συνθήκη.

⚠️ Πολυπλοκότητα

Αυτή η προσέγγιση είναι εκθετική γιατί δοκιμάζει όλα τα μονοπάτια. Για πραγματικά προβλήματα χρειάζονται αλγόριθμοι όπως Dijkstra ή A*. Στις εξετάσεις όμως, αυτή η δηλωτική προσέγγιση είναι αρκετή.

5. Δέντρα Επικάλυψης (Spanning Trees)

Ένα δέντρο επικάλυψης ενός συνδεδεμένου γράφου είναι ένας υπογράφος που:

🧠 Μνημονικός Κανόνας: Σ.Α.Σ.
  1. Συνεκτικότητα (Connected) — όλοι οι κόμβοι προσβάσιμοι
  2. Απουσία κύκλων (No cycles) — ακριβώς V-1 ακμές
  3. Σύνδεση όλων κορυφών (Covers all vertices)

Για γράφο [a-b, b-c, c-d, b-d] υπάρχουν 3 δέντρα επικάλυψης:

SpanningTree = [a-b, b-c, c-d] ή [a-b, b-d, d-c] ή [a-b, b-d, b-c]

5.1 Μέθοδος 1: Επεκτατική (spread)

Ξεκίνα με μια ακμή και προσθέτε μία-μία ακμές που συνδέουν "νέο" κόμβο με υπάρχοντα.

stree(Graph, Tree) :- member(Edge, Graph), spread([Edge], Tree, Graph). spread(Tree1, Tree, Graph) :- addedge(Tree1, Tree2, Graph), spread(Tree2, Tree, Graph). spread(Tree, Tree, Graph) :- not addedge(Tree, _, Graph). addedge(Tree, [A-B|Tree], Graph) :- adjacent(A, B, Graph), node(A, Tree), not node(B, Tree). % B είναι νέος κόμβος adjacent(N1, N2, Graph) :- member(N1-N2, Graph) ; member(N2-N1, Graph). node(Node, Graph) :- adjacent(Node, _, Graph).

5.2 Μέθοδος 2: Φιλτράρισμα (subset+tree)

Πάρε όλα τα υποσύνολα ακμών, και κράτα όσα είναι δέντρα (συνεκτικά + χωρίς κύκλους) και καλύπτουν τις κορυφές.

stree(Graph, Tree) :- subset(Graph, Tree), tree(Tree), covers(Tree, Graph). tree(Tree) :- connected(Tree), not hascycle(Tree). connected(Graph) :- not (node(A, Graph), node(B, Graph), not path(A, B, Graph, _)). hascycle(Graph) :- adjacent(N1, N2, Graph), path(N1, N2, Graph, [N1, X, _|_]). % μήκος ≥ 3
Μέθοδος 1 Επεκτατική

Γενετική — χτίζει σταδιακά. Πιο αποδοτική γιατί δεν εξετάζει αδύνατα υποσύνολα.

Μέθοδος 2 Φιλτράρισμα

Generate-and-test — πιο δηλωτική αλλά αργή για μεγάλους γράφους.

6. Αναζήτηση σε Χώρο Καταστάσεων

Πολλά προβλήματα Τεχνητής Νοημοσύνης λύνονται με τη μεθοδολογία της αναζήτησης σε χώρο καταστάσεων (state-space search):

  1. Αναπαράσταση κατάστασης — επιλογή δομής που περιγράφει "πώς μοιάζει ο κόσμος τώρα"
  2. Αρχική κατάσταση — όπου ξεκινάμε
  3. Τελική κατάσταση(εις) — που θέλουμε να φτάσουμε
  4. Δυνατές μεταπτώσεις — πώς πάμε από μια κατάσταση σε άλλη
  5. Αποφυγή κύκλων — λίστα ήδη επισκεφθέντων καταστάσεων

6.1 Γενικό Πλαίσιο DFS

Αυτό είναι το πιο σημαντικό κατηγόρημα του κεφαλαίου — η Εργασία 1 βασίζεται πάνω σε αυτό:

depth_first_search(States) :- initial_state(State), depth_first_search(State, [State], States). depth_first_search(State, States, States) :- final_state(State). % πέτυχε - φτάσαμε στο τέλος depth_first_search(State1, SoFarStates, States) :- move(State1, State2), % κάνε μια κίνηση not member(State2, SoFarStates), % αν είναι νέα κατάσταση append(SoFarStates, [State2], NewSoFarStates), depth_first_search(State2, NewSoFarStates, States).
depth_first_search(States) :-
Wrapper που αρχικοποιεί την αναζήτηση από την αρχική κατάσταση.
initial_state(State),
Διαβάζει την αρχική κατάσταση από κατηγόρημα που ορίζεται από το συγκεκριμένο πρόβλημα.
depth_first_search(State, States, States) :-
Βασική περίπτωση: αν η τρέχουσα κατάσταση είναι η τελική, η διαδρομή SoFarStates είναι η λύση.
final_state(State).
Έλεγχος ότι φτάσαμε στον στόχο — επίσης ορισμένο ανά πρόβλημα.
move(State1, State2),
Παίρνει νόμιμη μετάβαση από State1 σε νέα κατάσταση State2. Μη ντετερμινιστικό: η Prolog δοκιμάζει όλες τις δυνατές κινήσεις μέσω backtracking.
not member(State2, SoFarStates),
Κρίσιμη γραμμή! Αν δεν την έχουμε, η αναζήτηση θα κολλήσει σε άπειρους κύκλους.
append(SoFarStates, [State2], NewSoFarStates),
Προσθέτει τη νέα κατάσταση στο τέλος της διαδρομής.
depth_first_search(State2, NewSoFarStates, States).
Αναδρομική κλήση με την επεκτεταμένη διαδρομή.
📚 Για την Εργασία 1 (puzzle-5)

Το puzzle-5 είναι ένα 2×3 πλέγμα με 5 πλακάκια. Θα ορίσεις:

  • initial_state/1 — η αρχική θέση των πλακιδίων
  • final_state/1 — η τελική (συνήθως αριθμητική σειρά)
  • move/2 — κίνηση κενού πάνω/κάτω/αριστερά/δεξιά

Επιπλέον θα υλοποιήσεις LDFS (περιορισμένο βάθος) και IDS (επαναληπτική εμβάθυνση) — παραλλαγές του παραπάνω σχήματος.

6.2 Παράδειγμα 1: Αγρότης-Λύκος-Κατσίκα-Λάχανο

Ο αγρότης πρέπει να μεταφέρει λύκο, κατσίκα και λάχανο πέρα από ποτάμι. Η βάρκα χωράει μόνο αυτόν και ένα "είδος". Δεν πρέπει ποτέ να αφεθούν μόνοι ο λύκος με την κατσίκα ή η κατσίκα με το λάχανο.

Κατάσταση: fwgc(F, W, G, C) όπου το καθένα είναι l (αριστερά) ή r (δεξιά).

initial_state(fwgc(l, l, l, l)). final_state(fwgc(r, r, r, r)). move(fwgc(F1, W1, G1, C1), fwgc(F2, W2, G2, C2)) :- opposite(F1, F2), ((W1 = W2, G1 = G2, C1 = C2) ; % αγρότης μόνος (opposite(W1, W2), G1 = G2, C1 = C2) ; % παίρνει λύκο (W1 = W2, opposite(G1, G2), C1 = C2) ; % παίρνει κατσίκα (W1 = W2, G1 = G2, opposite(C1, C2))), % παίρνει λάχανο not illegal(fwgc(F2, W2, G2, C2)). illegal(fwgc(F, W, G, C)) :- opposite(F, G), % αγρότης μακριά από κατσίκα (G = W ; G = C). % και κατσίκα μόνη με λύκο ή λάχανο opposite(l, r). opposite(r, l).

6.3 Παράδειγμα 2: Ιεραπόστολοι & Κανίβαλοι

3 ιεραπόστολοι και 3 κανίβαλοι πρέπει να διασχίσουν ποτάμι με βάρκα 2 ατόμων. Σε καμία όχθη οι κανίβαλοι δεν πρέπει να ξεπερνούν αριθμητικά τους ιεραπόστολους.

Κατάσταση: state(MB, CB, B) όπου MB = ιεραπόστολοι στην όχθη της βάρκας, CB = κανίβαλοι στην ίδια όχθη, B = πλευρά της βάρκας.

6.4 Παράδειγμα 3: Δοχεία Νερού (Water Jugs)

Έχουμε δύο κανάτες 8L και 5L (χωρίς ένδειξη). Στόχος: 4L στην πρώτη.

Κατάσταση: jugs(V1, V2) με τους τρέχοντες όγκους.

initial_state(jugs(0, 0)). final_state(jugs(4, 0)). move(jugs(V1, V2), jugs(W1, W2)) :- C1 = 8, C2 = 5, L is V1 + V2, ((V1 < C1, W1 = C1, W2 = V2) ; % γέμισμα 1 (V2 < C2, W1 = V1, W2 = C2) ; % γέμισμα 2 (V1 > 0, W1 = 0, W2 = V2) ; % άδειασμα 1 (V2 > 0, W1 = V1, W2 = 0) ; % άδειασμα 2 (minimax(L, C2, W2), W1 is L - W2) ; % μετάγγιση 1→2 (minimax(L, C1, W1), W2 is L - W1)). % μετάγγιση 2→1 minimax(X, Y, X) :- X =< Y. minimax(X, Y, Y) :- X > Y.

6.5 Πίθηκος-Μπανάνα (Επανάληψη από Κεφάλαιο 1)

Είδαμε το κλασικό αυτό παράδειγμα στο Κεφάλαιο 1. Εδώ απλώς θυμίζουμε ότι ταιριάζει ακριβώς στο πλαίσιο DFS:

canget(state(_, _, _, has)). canget(State1) :- move(State1, _, State2), canget(State2).
⚠️ Διαφορά από το γενικό σχήμα

Σε αυτή την έκδοση δεν κρατάμε λίστα επισκεφθέντων καταστάσεων! Λειτουργεί επειδή κάθε ενέργεια αλλάζει την κατάσταση μονότονα (κίνηση πιθήκου, σπρώξιμο κιβωτίου, σκαρφάλωμα, αρπαγή) χωρίς πιθανότητα να επιστρέψει σε προηγούμενη κατάσταση. Σε γενικά CSPs χρειάζεται ο έλεγχος.

7. Λογικοί Γρίφοι & Προβλήματα Ικανοποίησης Περιορισμών

Σε CSPs (Constraint Satisfaction Problems) έχουμε μεταβλητές, καθεμία με ένα πεδίο ορισμού τιμών, και περιορισμούς που συνδέουν τιμές. Στόχος: ανάθεση τιμών που ικανοποιεί όλους τους περιορισμούς.

7.1 Δύο Στρατηγικές Επίλυσης

Αργό Generate-and-Test

Παράγει όλες τις δυνατές αναθέσεις και μετά ελέγχει αν ικανοποιούν τους περιορισμούς. Εκθετικό.

go(X, Y) :- generate(People), test(People).
Γρήγορο Constrain-and-Generate

Εφαρμόζει τους περιορισμούς πριν και κατά τη διάρκεια της δημιουργίας τιμών. Κλαδεύει το δέντρο αναζήτησης άμεσα.

go(X, Y) :- test(People), generate(People).
💡 Η μαγεία της Prolog

Παρατήρησε ότι ο κώδικας είναι σχεδόν ίδιος — μόνο η σειρά αλλάζει! Αυτή είναι η δηλωτική φύση της Prolog: αναδιατάσσοντας στόχους αλλάζουμε δραστικά την αποδοτικότητα χωρίς να αλλάξουμε τη σημασία.

7.2 Το Πρόβλημα της Ζέβρας

Πέντε άνθρωποι διαφορετικών εθνικοτήτων μένουν σε πέντε συνεχόμενα σπίτια. Καθένας έχει διαφορετικό επάγγελμα, αρέσει διαφορετικό ποτό, και έχει διαφορετικό κατοικίδιο. Τα πέντε σπίτια έχουν διαφορετικά χρώματα.

1Ο Άγγλος μένει στο κόκκινο σπίτι.
2Ο Ισπανός έχει σκύλο.
3Ο Ιαπωνέζος είναι ζωγράφος.
4Ο Ιταλός πίνει τσάι.
5Ο Νορβηγός μένει στο πρώτο σπίτι.
6Το πράσινο σπίτι: καφές.
7Πράσινο σπίτι δεξιά από άσπρο.
8Ο γλύπτης έχει σαλιγκάρια.
9Ο διπλωμάτης ζει στο κίτρινο.
10Το μεσαίο σπίτι: γάλα.
11Ο Νορβηγός δίπλα σε μπλε.
12Ο βιολιστής πίνει χυμό.
13Αλεπού δίπλα σε γιατρό.
14Άλογο δίπλα σε διπλωμάτη.

Ερωτήσεις: Ποιος έχει τη ζέβρα; Ποιος πίνει νερό;

Αναπαράσταση:

Κάθε άτομο είναι 6-τάδα: (Nationality, Profession, Animal, Drink, Colour, HouseId). Η λίστα των πέντε ατόμων είναι ταξινομημένη κατά θέση (1 έως 5).

% --- Constrain-and-Generate (πιο γρήγορο) --- go(ZebraOwner, WaterDrinker) :- nationalities(People), % σκελετός: 5 διαφορετικές test(People), % εφαρμόζει περιορισμούς generate(People), % συμπληρώνει τα πεδία member((ZebraOwner, _, zebra, _, _, _), People), member((WaterDrinker, _, _, water, _, _), People). nationalities([(english,_,_,_,_,_), (spanish,_,_,_,_,_), (japanese,_,_,_,_,_), (italian,_,_,_,_,_), (norwegian,_,_,_,_,_)]). test(P) :- rule1(P), rule2(P), ..., rule14(P). rule1(P) :- member((english,_,_,_,red,_), P). rule2(P) :- member((spanish,_,dog,_,_,_), P). rule3(P) :- member((japanese,painter,_,_,_,_), P). % ... κλπ, όλοι οι κανόνες ως μέλη της λίστας rule5(P) :- member((norwegian,_,_,_,_,1), P). rule7(P) :- member((_,_,_,_,green,IDG), P), member((_,_,_,_,white,IDW), P), rightof(IDG, IDW). rule11(P) :- member((norwegian,_,_,_,_,IDN), P), member((_,_,_,_,blue,IDB), P), nextto(IDN, IDB). nextto(X, Y) :- rightof(X, Y) ; rightof(Y, X). rightof(2,1). rightof(3,2). rightof(4,3). rightof(5,4).
⚠️ Generate-and-Test εκδοχή

Αν αντιστρέψεις τη σειρά (πρώτα generate, μετά test), η Prolog θα παράγει όλους τους 5!×5!×5!×5! ≈ 200 εκατομμύρια συνδυασμούς πριν δοκιμάσει τους περιορισμούς. Πρακτικά: ποτέ δεν τελειώνει.

Με constrain-and-generate, η λύση βρίσκεται σε δευτερόλεπτα. Η απάντηση: Z = japanese, W = norwegian.

7.3 Το Πρόβλημα των N Βασιλισσών

Τοποθέτησε N βασίλισσες σε σκακιέρα N×N ώστε καμία να μην απειλεί άλλη (καμία στην ίδια γραμμή, στήλη ή διαγώνιο).

Αναπαράσταση:

Λίστα [Q1, Q2, ..., QN] όπου το Qi είναι η στήλη της βασίλισσας στη γραμμή i. Επειδή μία ανά γραμμή, αυτόματα δεν συγκρούονται οριζόντια. Επειδή θέλουμε μετάθεση του [1..N], δεν συγκρούονται και κάθετα. Μένει μόνο η διαγώνιος.

🧠 Δύο βασίλισσες στις θέσεις (x₁,y₁) και (x₂,y₂) είναι σε διαγώνιο όταν:
  • x₁ - y₁ = x₂ - y₂  (κύρια διαγώνιος u)
  • x₁ + y₁ = x₂ + y₂  (δευτερεύουσα διαγώνιος v)
% Απλή έκδοση με permutation + έλεγχο διαγωνίου queens(N, Qs) :- numlist(1, N, Ns), permutation(Ns, Qs), safe(Qs). safe([]). safe([Q|Qs]) :- no_attack(Q, Qs, 1), safe(Qs). no_attack(_, [], _). no_attack(Q, [Q1|Qs], D) :- Q1 - Q =\= D, % όχι κάτω-δεξιά διαγώνιος Q - Q1 =\= D, % όχι πάνω-δεξιά διαγώνιος D1 is D + 1, no_attack(Q, Qs, D1).

7.4 Πρόβλημα Χρωματισμού Χάρτη

Δίνονται χώρες με πληροφορία γειτνίασης. Χρωμάτισε τες με ≤4 χρώματα ώστε γειτονικές χώρες να μην έχουν ίδιο χρώμα.

colour(red). colour(blue). colour(green). colour(yellow). % Παράδειγμα: BeNeLux χώρες neighbours(belgium, [netherlands, luxembourg, germany, france]). neighbours(netherlands, [belgium, germany]). % ... map_colour([], _). map_colour([Country-Colour | Rest], Assigned) :- colour(Colour), neighbours(Country, Ns), \+ (member(N, Ns), member(N-Colour, Assigned)), map_colour(Rest, [Country-Colour|Assigned]).
📝 Το Θεώρημα των Τεσσάρων Χρωμάτων

Αποδείχθηκε μαθηματικά (Appel-Haken, 1976) ότι κάθε επίπεδος χάρτης μπορεί να χρωματιστεί με μόνο 4 χρώματα. Πρώτη αξιοσημείωτη μαθηματική απόδειξη που εκτελέστηκε εν μέρει από υπολογιστή.

💡 Τελικές Συμβουλές για Σωστό Κώδικα

  1. Σειρά κανόνων: Πάντα η περίπτωση βάσης (nil, []) πρώτη, μετά η αναδρομική. Αλλιώς κίνδυνος άπειρης ανακύκλωσης.
  2. Constraints early: Σε γρίφους, εφάρμοσε τους περιορισμούς ΠΡΙΝ τη γέννηση τιμών. Κλαδεύει εκθετικά.
  3. Visited list: Σε αναζήτηση καταστάσεων, πάντα ελέγχει not member(NewState, Visited).
  4. Πράσινα cuts: Χρήσιμα για αποδοτικότητα (π.χ. στο swap της bubblesort) αλλά μην αλλάζουν σημασία.
  5. Αναπαράσταση κατάστασης: Διάλεξε αναπαράσταση που να περιγράφει πλήρως τον κόσμο και να επιτρέπει εύκολο έλεγχο τελικής κατάστασης.
