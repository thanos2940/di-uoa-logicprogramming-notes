2. Χειρισμός Όρων (Term Manipulation)

Η Prolog μας επιτρέπει να αναλύσουμε και να συνθέσουμε όρους δυναμικά. Αυτό είναι το θεμέλιο του μετα-προγραμματισμού: ένα πρόγραμμα που γράφει/τροποποιεί άλλα προγράμματα.

2.1 Ο Τελεστής "Universe": =..

Ο univ (=..) μετατρέπει έναν όρο σε λίστα [Functor | Args] και αντιστρόφως:

date(1, may, 1983)
⇔
date1may1983
?- date(1, may, 1983) =.. L. L = [date, 1, may, 1983] ?- T =.. [parent, tom, bob]. T = parent(tom, bob)
💡 Κλασική Χρήση: Δυναμική Δημιουργία Στόχου

Συνδυάζοντας με το call/1, μπορούμε να φτιάξουμε στόχους από κομμάτια:

% Καλέσε δυναμικά κατηγόρημα Rel με ορίσματα Arg1, Arg2 invoke(Rel, Arg1, Arg2) :- Goal =.. [Rel, Arg1, Arg2], call(Goal). ?- invoke(parent, tom, X). X = bob

2.2 functor/3 — Όνομα και Αριθμός Ορισμάτων

?- functor(date(1,may,1983), F, N). F = date, N = 3 ?- functor(T, parent, 2). T = parent(_G123, _G124) % κενός όρος με σωστή δομή!

Το functor/3 χρησιμεύει για δύο σκοπούς:

  1. Ανάλυση: "δώσε μου το όνομα και την αριθμότητα ενός όρου"
  2. Σύνθεση: "φτιάξε έναν κενό όρο με δεδομένο όνομα και αριθμό ορισμάτων"

2.3 arg/3 — Πρόσβαση σε Ορίσματα

?- arg(1, date(1,may,1983), X). X = 1 ?- arg(2, parent(tom, bob), Y). Y = bob

2.4 call/1 — Εκτέλεση Δυναμικού Στόχου

Το call(Goal) εκτελεί τον στόχο που υπολογίστηκε δυναμικά:

happy(tom). happy(ann). ?- X = happy(tom), call(X). yes

2.5 Σύνθεση: maplist/3

Ο κλασικός τρόπος υλοποίησης του map (εφαρμογή κατηγορήματος σε κάθε στοιχείο λίστας) χρησιμοποιεί όλα τα παραπάνω:

maplist([], _, []). maplist([X|Tail], F, [NewX|NewTail]) :- G =.. [F, X, NewX], % φτιάξε στόχο F(X, NewX) call(G), % εκτέλεσέ τον maplist(Tail, F, NewTail).
square(X, Y) :- Y is X*X. ?- maplist([1,2,3,4], square, L). L = [1, 4, 9, 16]
🧠 Διάγραμμα Σύνδεσης Term ↔ List

Σκέψου το =.. ως "ζίπερ" που ανοίγει/κλείνει τη δομή. functor = "πάρε όνομα + arity". arg(N, T, X) = "δάκτυλο που δείχνει στο N-οστό όρισμα". call = "ναι, εκτέλεσέ το τώρα".

⚠️ Προσοχή στις Μεταβλητές

Το =.. απαιτεί τουλάχιστον ένα από τα δύο μέλη να είναι αρκετά καθορισμένο. X =.. Y με δύο άγνωστα δίνει σφάλμα.

3. Δυναμική Βάση Δεδομένων

Η Prolog επιτρέπει αλλαγή της βάσης γνώσης κατά τη διάρκεια εκτέλεσης: προσθήκη και διαγραφή προτάσεων. Αυτό είναι ισχυρό αλλά και επικίνδυνο.

3.1 Τα Κατηγορήματα Αλλαγής

ΚατηγόρημαΛειτουργία
assert(P)Προσθήκη πρότασης P (συνήθως == assertz)
asserta(P)Προσθήκη στην αρχή της βάσης
assertz(P)Προσθήκη στο τέλος της βάσης
retract(P)Αφαίρεση πρώτης πρότασης που ταιριάζει με P
abolish(F/N)Διαγραφή όλων των προτάσεων με όνομα F και arity N

3.2 Παράδειγμα

?- assert(p(1)). yes ?- assert(p(2)). yes ?- p(X). X = 1 -> ; X = 2 -> ; no ?- retract(p(X)). X = 1 -> ; X = 2 -> ; no ?- p(X). no
⚠️ Δήλωση dynamic

Στη SWI-Prolog (και άλλες σύγχρονες), κάθε κατηγόρημα που θα τροποποιηθεί δυναμικά πρέπει να δηλωθεί:

:- dynamic p/1.

Αλλιώς το assert(p(1)) θα αποτύχει με σφάλμα "static procedure".

3.3 Παράδειγμα: Memoization Fibonacci

Η αναδρομική Fibonacci έχει O(2ⁿ) πολυπλοκότητα γιατί υπολογίζει τα ίδια fib ξανά και ξανά. Με memoization την κάνουμε γραμμική:

:- dynamic memo_fib/2. fib(N, V) :- memo_fib(N, V), !. % Έχουμε ήδη υπολογίσει; επέστρεψε fib(0, 0) :- !, assertz(memo_fib(0, 0)). fib(1, 1) :- !, assertz(memo_fib(1, 1)). fib(N, V) :- N1 is N - 1, N2 is N - 2, fib(N1, V1), fib(N2, V2), V is V1 + V2, assertz(memo_fib(N, V)). % αποθήκευσε για μελλοντική χρήση

3.4 Ο Συνδυασμός repeat-fail και Συλλογή Λύσεων

Πιθανώς εκπληκτικό: το findall/3 μπορεί να οριστεί μέσω assert/retract:

findall(X, Goal, Xlist) :- call(Goal), assert(queue(X)), fail ; assert(queue(bottom)), collect(Xlist). collect(L) :- retract(queue(X)), !, (X == bottom, !, L=[] ; L=[X|Rest], collect(Rest)).
⚠️ Σοβαρή Προειδοποίηση

Τα assert/retract βλάπτουν σοβαρά τη δηλωτικότητα ενός προγράμματος Prolog. Πρέπει να χρησιμοποιούνται μόνο σε εξειδικευμένες περιπτώσεις (memoization, δυναμικές βάσεις γνώσης). Σε νόρμα προγραμματισμό, είναι σαν το GOTO των διαδικαστικών γλωσσών.

4. Έλεγχος Ροής: repeat/0

4.1 Το repeat/0 Πρωτογενές

Το repeat/0 είναι ένα προεγκατεστημένο κατηγόρημα που πάντα πετυχαίνει, και με backtracking μπορεί να επανεκτελεστεί άπειρες φορές:

repeat. repeat :- repeat. ?- repeat. yes -> ; yes -> ; yes -> ; ... (άπειρες φορές)

4.2 Το Σχήμα repeat-fail

Συνδυάζεται με fail για να δημιουργήσει βρόχο επανάληψης μέχρι κάποια συνθήκη:

dosquares :- repeat, read(X), (X = stop, ! % Αν stop, δέσμευσε και τέλος ; Y is X * X, write(Y), nl, fail). % αλλιώς fail → ξαναπροσπάθησε

Παράδειγμα εκτέλεσης:

?- dosquares. |: 7. 49 |: 10. 100 |: 3. 9 |: stop. yes
repeat,
Δημιουργεί επιλογή σημείο (choice point). Με κάθε αποτυχία (fail), επιστρέφει εδώ.
read(X),
Διαβάζει είσοδο.
(X = stop, !
Αν X είναι "stop", το cut κόβει όλα τα choice points και ολοκληρώνει.
; ... fail).
Αλλιώς, υπολόγισε, γράψε, και επιβολή fail: η Prolog θα επιστρέψει στο repeat και θα ξαναξεκινήσει.
💡 Πότε χρησιμοποιείται

Το repeat-fail είναι χρήσιμο για επαναληπτικές διαδικασίες με παρενέργειες (Ι/Ο, ανάγνωση αρχείου, αλληλεπίδραση). Σε καθαρά δηλωτικό κώδικα, προτιμάμε αναδρομή!

⚠️ Πάντα χρειάζεσαι έξοδο

Πρέπει να υπάρχει ! (cut) στη συνθήκη εξόδου, αλλιώς ο βρόχος δεν τερματίζει ποτέ.

5. Κατηγορήματα Συλλογής Λύσεων

Η αναζήτηση στην Prolog μέσω backtracking δίνει μία λύση κάθε φορά. Αλλά συχνά θέλουμε όλες τις λύσεις μαζί σε λίστα. Για αυτό υπάρχουν τα findall/3, bagof/3, setof/3.

5.1 Συγκριτικός Πίνακας

ΚατηγόρημαΤαξινόμησηΔιπλότυπαΣε αποτυχίαΟμαδοποίηση
findall/3ΌχιΔιατηρείΕπιστρέφει []Καμία
bagof/3ΌχιΔιατηρείΑποτυχία (no)Ναι (με ^)
setof/3ΝαιΑφαιρείΑποτυχία (no)Ναι (με ^)

5.2 Παράδειγμα Βάσης

age(peter, 7). age(ann, 5). age(pat, 8). age(tom, 5).

5.3 findall/3

"Δώσε μου τη λίστα όλων των X που ικανοποιούν τον στόχο":

?- findall(Child, age(Child, Age), List). List = [peter, ann, pat, tom] ?- findall(Child, age(Child, 5), List). List = [ann, tom] ?- findall(X, bla(X), L). % bla δεν υπάρχει L = [] % σιωπηρά επιστρέφει κενή

5.4 bagof/3 και setof/3

Η σημαντική διαφορά είναι ότι bagof και setof αποτυγχάνουν αν δεν υπάρχουν λύσεις:

?- bagof(Child, age(Child, 5), List). List = [ann, tom] ?- bagof(X, bla(X), L). no % αποτυγχάνει αντί να δώσει []

Επιπλέον, ομαδοποιούν αυτόματα ανά ελεύθερες μεταβλητές του στόχου!

?- bagof(Child, age(Child, Age), List). Age = 5, List = [ann, tom] -> ; Age = 7, List = [peter] -> ; Age = 8, List = [pat] -> ; no
📝 Γιατί αυτό συμβαίνει

Το Age είναι ελεύθερη μεταβλητή στον στόχο age(Child, Age). Το bagof ομαδοποιεί τα αποτελέσματα ξεχωριστά για κάθε τιμή του Age — σαν να κάνει "GROUP BY Age" σε SQL!

5.5 Ο Τελεστής ^ (Existential Quantification)

Αν θέλουμε να αγνοήσουμε την ομαδοποίηση κατά μια μεταβλητή, χρησιμοποιούμε το ^:

?- bagof(Child, Age^age(Child, Age), List). List = [peter, ann, pat, tom] % όλα μαζί! ?- bagof(Age, Child^age(Child, Age), List). List = [7, 5, 8, 5] % όλες οι ηλικίες
🧠 Διάβασε το Age^Goal ως: "για κάποιο Age, ο στόχος αληθεύει"

Στα μαθηματικά: ∃Age. Goal. Δηλαδή, μην ομαδοποιείς ανά Age — απλώς δώσε μου ό,τι ικανοποιεί τον στόχο για οποιοδήποτε Age.

5.6 setof/3 — Ταξινομημένο, χωρίς διπλότυπα

?- setof(Age, Child^age(Child, Age), AgeList). AgeList = [5, 7, 8] % ταξινομημένο, χωρίς διπλότυπα ?- setof(Child, Age^age(Child, Age), ChildList). ChildList = [ann, pat, peter, tom] % αλφαβητικά

5.7 Σύνθετα Παραδείγματα με Ζευγάρια

Μπορούμε να συλλέξουμε δομές:

?- setof(Age/Child, age(Child, Age), List). List = [5/ann, 5/tom, 7/peter, 8/pat]
💡 Επειδή ταξινομεί κατά πρώτο στοιχείο

Συλλέγοντας ζευγάρια Age/Child, το αποτέλεσμα είναι ταξινομημένο πρώτα κατά Age και μετά κατά Child — χρήσιμο "two-key sort" δωρεάν!

5.8 Σχέση με την Εργασία 3 (job-shop)

📚 Για την Εργασία 3

Η εργασία ζητάει χρήση του findall για να μετρηθούν όλες οι λύσεις:

?- findall(S, jobshop(S), L), length(L, N). N = 9136

Το findall πρακτικά εξαναγκάζει την Prolog να αντισκευάσει όλες τις λύσεις μέσω backtracking, και τις συλλέγει σε μία λίστα. Η length μετράει.

6. Μετα-Προγραμματισμός & Κλασικές Εφαρμογές

Στον μετα-προγραμματισμό, γράφουμε προγράμματα Prolog για να επεξεργαστούν άλλα προγράμματα Prolog. Είναι μια από τις πιο εκπληκτικές δυνατότητες της γλώσσας.

6.1 Ένας Διερμηνέας Prolog σε Prolog

Με ~5 γραμμές κώδικα μπορούμε να γράψουμε διερμηνέα της Prolog μέσα στην ίδια την Prolog:

% Αναπαριστώμε προτάσεις ως cl(Head, Body) όπου Body είναι λίστα στόχων cl(member(X, [X|_]), []). cl(member(X, [_|L]), [member(X, L)]). % Ο διερμηνέας execute([]). execute([Goal|Goals]) :- cl(Goal, Body), append(Body, Goals, NewGoals), execute(NewGoals). ?- execute([member(X, [1,2,3]), member(X, [2,3,4])]). X = 2 -> ; X = 3 yes
📝 Γιατί μετράει αυτό

Έχοντας έλεγχο πάνω στον "διερμηνέα", μπορούμε να τον τροποποιήσουμε. Π.χ. να καταγράφει αποδεικτικά μονοπάτια ("γιατί", "πώς"), να χειρίζεται αβέβαιη πληροφορία (βαθμοί βεβαιότητας), ή να υλοποιεί διαφορετική στρατηγική αναζήτησης (BFS αντί DFS).

6.2 Συμβολική Παραγώγηση

Το παρακάτω πρόγραμμα μπορεί να παραγωγίσει αυτόματα οποιαδήποτε αλγεβρική έκφραση:

% diff(Expression, Variable, Derivative) diff(C, X, 0) :- integer(C). % d(c)/dx = 0 diff(X, X, 1). % d(x)/dx = 1 diff(U + V, X, DU + DV) :- diff(U, X, DU), diff(V, X, DV). diff(-U, X, -DU) :- diff(U, X, DU). diff(U - V, X, DU - DV) :- diff(U, X, DU), diff(V, X, DV). diff(C * U, X, C * DU) :- integer(C), diff(U, X, DU). diff(U * V, X, U * DV + V * DU) :- diff(U, X, DU), diff(V, X, DV). diff(U / V, X, (V*DU - U*DV) / V^2) :- diff(U, X, DU), diff(V, X, DV). diff(U^C, X, C*U^(C-1)*DU) :- integer(C), diff(U, X, DU). diff(sin(U), X, cos(U) * DU) :- diff(U, X, DU).
?- diff(3*x^2 + sin(x), x, D). D = 3*(2*x^1*1) + cos(x)*1
💡 Πώς δουλεύει

Κάθε μαθηματικός κανόνας παραγώγησης γίνεται μια πρόταση Prolog. Η Prolog τους εφαρμόζει αναδρομικά μέχρι να καταλήξει σε αριθμούς. Το αποτέλεσμα είναι μη απλοποιημένο — απλοποίηση είναι ξεχωριστή άσκηση.

6.3 Προσομοίωση Λογικών Κυκλωμάτων

Δίνεται ένα κύκλωμα ως όρος, π.χ.:

circuit(c1, nor(and(nt(X), Y), nand(or(X, Y), Z)), [X, Y, Z]).

Μπορούμε να υπολογίσουμε την έξοδό του:

circ(1, 1) :- !. circ(0, 0) :- !. circ(and(X, Y), 1) :- circ(X, 1), circ(Y, 1). circ(and(X, Y), 0) :- circ(X, 1), circ(Y, 0). circ(and(X, Y), 0) :- circ(X, 0), circ(Y, 1). circ(and(X, Y), 0) :- circ(X, 0), circ(Y, 0). circ(or(X, Y), 1) :- circ(X, 1), circ(Y, 1). circ(or(X, Y), 1) :- circ(X, 1), circ(Y, 0). circ(or(X, Y), 1) :- circ(X, 0), circ(Y, 1). circ(or(X, Y), 0) :- circ(X, 0), circ(Y, 0). circ(nt(X), 1) :- circ(X, 0). circ(nt(X), 0) :- circ(X, 1). circ(nand(X, Y), Z) :- circ(nt(and(X, Y)), Z). circ(nor(X, Y), Z) :- circ(nt(or(X, Y)), Z).
?- circuit(c1, C, [1, 0, 1]), circ(C, Out). Out = 0 % Αντίστροφα: για ποιες εισόδους Out = 1; ?- circuit(c1, C, Inputs), circ(C, 1). Inputs = [...]
💡 Πανίσχυρο

Επειδή ο κώδικας είναι αμφίδρομος, μπορούμε να ρωτήσουμε "για ποιες εισόδους η έξοδος είναι 1;" — η Prolog θα δοκιμάσει όλους τους συνδυασμούς και θα μας πει.

6.4 Κατανόηση Φυσικής Γλώσσας (NL Parsing)

Δηλωτικός parser που μετατρέπει αγγλικές προτάσεις σε λογικούς τύπους:

:- op(190, yfx, :). :- op(180, yfx, ==>). :- op(170, yfx, &). sentence(L, P) :- sentence(L, [], P). sentence(L1, L3, P) :- noun_phrase(L1, L2, X, P1, P), verb_phrase(L2, L3, X, P1). noun_phrase(L1, L2, X, P, P) :- name(L1, L2, X). verb_phrase(L1, L2, X, P) :- intrans_verb(L1, L2, X, P). determiner([every|L], L, X, P1, P2, all(X):(P1==>P2)). determiner([a|L], L, X, P1, P2, exists(X):(P1&P2)). noun([man|L], L, X, man(X)). name([john|L], L, john). intrans_verb([lives|L], L, X, lives(X)).
?- sentence([john, lives], P). P = lives(john) ?- sentence([every, man, that, loves, john, hates, every, woman], P). P = all(_X):((man(_X) & loves(_X, john)) ==> ...)

7. Έμπειρα Συστήματα (Expert Systems)

Ένα έμπειρο σύστημα προσομοιώνει τη συμπεριφορά ειδικού σε περιορισμένο γνωστικό πεδίο (π.χ. ιατρική διάγνωση, μηχανικές βλάβες). Είναι κλασικό παράδειγμα knowledge-based system.

7.1 Δομή Έμπειρου Συστήματος

Η γνώση αναπαρίσταται με κανόνες παραγωγής (production rules) τύπου IF condition THEN conclusion.

7.2 Το Πρόβλημα Διάγνωσης: Διαρροή Νερού

Διαγνωστικό σύστημα για διαρροές σε κατοικία:

Οι κανόνες σε φυσική γλώσσα:

  • IF kitchen_dry AND hall_wet THEN leak_in_bathroom
  • IF hall_wet AND bathroom_dry THEN problem_in_kitchen
  • IF window_closed OR no_rain THEN no_water_from_outside
  • IF problem_in_kitchen AND no_water_from_outside THEN leak_in_kitchen

7.3 Προσέγγιση Α': Απλή Prolog (Backward Chaining)

Η πιο απλή λύση: γράψε τους κανόνες ως κανόνες Prolog. Η ενσωματωμένη μηχανή resolution κάνει τη δουλειά:

leak_in_bathroom :- kitchen_dry, hall_wet. problem_in_kitchen :- hall_wet, bathroom_dry. no_water_from_outside :- window_closed ; no_rain. leak_in_kitchen :- problem_in_kitchen, no_water_from_outside. hall_wet. bathroom_dry. window_closed. ?- leak_in_kitchen. yes
⚠️ Περιορισμός

Δεν προσφέρει εξηγήσεις ή βεβαιότητα. Επίσης, δεν διαχωρίζει τη γνώση από τη μηχανή συμπερασμού.

7.4 Προσέγγιση Β': Backward Chaining Meta-Interpreter

Διαχωρίζουμε τους κανόνες ("γνώση") από τη μηχανή συμπερασμού ("inference engine"):

:- op(800, fx, if). :- op(700, xfx, then). :- op(300, xfy, or). :- op(200, xfy, and). % --- Knowledge base με συντακτικό φυσικότερο --- if kitchen_dry and hall_wet then leak_in_bathroom. if window_closed or no_rain then no_water_from_outside. % ... fact(hall_wet). fact(bathroom_dry). fact(window_closed). % --- Inference Engine: backward chaining --- is_true(P) :- fact(P). is_true(P) :- if Condition then P, % βρες κανόνα με συμπέρασμα P is_true(Condition). % αναδρομικά απόδειξε τη συνθήκη is_true(P1 and P2) :- is_true(P1), is_true(P2). is_true(P1 or P2) :- is_true(P1) ; is_true(P2). ?- is_true(leak_in_kitchen). yes
🧠 Backward Chaining = Goal-Driven

"Ξεκινάω από αυτό που θέλω να αποδείξω, και ψάχνω προς τα πίσω για κανόνες/γεγονότα που το στηρίζουν." Είναι η φυσική φορά της Prolog.

7.5 Προσέγγιση Γ': Forward Chaining Meta-Interpreter

Αντίθετα, ξεκινάμε από τα γεγονότα και προχωράμε προς συμπεράσματα:

forward :- new_derived_fact(P), !, write('Derived: '), write(P), nl, assert(fact(P)), forward. % αναζήτησε επόμενο forward :- write('No more facts'). new_derived_fact(Concl) :- if Cond then Concl, % βρες κανόνα not fact(Concl), % του οποίου το συμπέρασμα δεν ξέρουμε ήδη composed_fact(Cond). % και του οποίου οι συνθήκες είναι αληθείς composed_fact(Cond) :- fact(Cond). composed_fact(C1 and C2) :- composed_fact(C1), composed_fact(C2). composed_fact(C1 or C2) :- composed_fact(C1) ; composed_fact(C2). ?- forward. Derived: problem_in_kitchen Derived: no_water_from_outside Derived: leak_in_kitchen No more facts

7.6 Backward vs Forward: Πότε Ποιο;

Backward Goal-Driven

Πότε: Έχουμε συγκεκριμένο στόχο ("πάσχει ο ασθενής από Χ;"). Λίγοι τελικοί στόχοι, πολλά πιθανά γεγονότα.

Παραδείγματα: ιατρική διάγνωση, νομικά συμπεράσματα.

Forward Data-Driven

Πότε: Έχουμε πολλά γεγονότα και θέλουμε να δούμε τι συμπεράσματα προκύπτουν. Λίγα αρχικά γεγονότα, πολλοί δυνατοί στόχοι.

Παραδείγματα: monitoring/alarm systems, εφαρμογές διάγνωσης σε real-time.

7.7 Επέκταση: Παροχή Εξηγήσεων

Επεκτείνουμε τον meta-interpreter ώστε να καταγράφει πώς αποδείχθηκε κάτι:

:- op(800, xfx, <=). is_true(P, P) :- fact(P). is_true(P, P <= CondProof) :- if Cond then P, is_true(Cond, CondProof). is_true(P1 and P2, Proof1 and Proof2) :- is_true(P1, Proof1), is_true(P2, Proof2). is_true(P1 or P2, Proof) :- is_true(P1, Proof) ; is_true(P2, Proof).

7.8 Χειρισμός Αβέβαιης Πληροφορίας

Σε πραγματικά συστήματα, η γνώση δεν είναι 100% σίγουρη. Εισάγουμε συντελεστές βεβαιότητας (certainty factors) 0 ≤ c ≤ 1:

given(hall_wet, 1). given(bathroom_dry, 1). given(kitchen_dry, 0). given(no_rain, 0.8). % δεν είμαστε σίγουροι given(window_closed, 0). % Κανόνες με συντελεστές if hall_wet and bathroom_dry then problem_in_kitchen : 0.9. if window_closed or no_rain then no_water_from_outside : 1. % Κανόνες σύνθεσης συντελεστών: % c(P1 and P2) = min(c(P1), c(P2)) % c(P1 or P2) = max(c(P1), c(P2)) % c(P) = c(P1) * c αν "if P1 then P : c" certainty(P, Cert) :- given(P, Cert). certainty(P1 and P2, Cert) :- certainty(P1, C1), certainty(P2, C2), minimum(C1, C2, Cert). certainty(P1 or P2, Cert) :- certainty(P1, C1), certainty(P2, C2), maximum(C1, C2, Cert). certainty(P, Cert) :- if Cond then P : C1, certainty(Cond, C2), Cert is C1 * C2. ?- certainty(leak_in_kitchen, C). C = 0.8
💡 Κλασικό σύστημα: MYCIN

Το MYCIN (Buchanan & Shortliffe, 1975-85) ήταν το πρώτο σημαντικό έμπειρο σύστημα. Διέγνωσκε μολυσματικές ασθένειες και πρότεινε θεραπεία. Χρησιμοποιούσε ακριβώς τέτοιους συντελεστές βεβαιότητας.

8. Αρχές Καλού Προγραμματισμού σε Prolog

Ένα καλό πρόγραμμα — ανεξάρτητα γλώσσας — πρέπει να είναι:

  • Σωστό — δίνει τις σωστές απαντήσεις
  • Αποδοτικό — μνήμη και χρόνος υπό έλεγχο
  • Ευανάγνωστο — άλλος προγραμματιστής το καταλαβαίνει
  • Εύκολα τροποποιήσιμο — προστίθεται/αλλάζει χαρακτηριστικό χωρίς να σπάσει
  • Εύρωστο — αντέχει σε λανθασμένη χρήση
  • Τεκμηριωμένο — έχει σχόλια εκεί που χρειάζονται

8.1 Σταδιακή Εκλέπτυνση (Stepwise Refinement)

Ξεκίνα από γενικό και πήγαινε σε ειδικό. Π.χ. αν θέλεις λύτη "8 βασιλισσών", πρώτα ορίζεις nqueens(Pos, N) για γενικό N, και μετά:

eightqueens(Pos) :- nqueens(Pos, 8).

Πιο εύκολο να σχεδιαστεί η γενική περίπτωση από τη συγκεκριμένη.

8.2 Προτιμάτε Αναδρομή από repeat-fail

Κακή
main :- repeat, read(X), process(X), X = stop, !.

Δύσκολο να ακολουθηθεί η ροή

Καλή
main :- read(X), main(X). main(stop) :- !. main(X) :- process(X), main.

Καθαρή αναδρομή, αναγνωρίσιμη δομή

8.3 Δέκα Κανόνες Σωστής Prolog

  1. Μικρές προτάσεις — με λίγους στόχους ανά πρόταση
  2. Μνημονικά ονόματα — parent_of καλύτερο από p
  3. Διαρρύθμιση — στοίχιση, κενές γραμμές, σωστή εμφάνιση
  4. Ομαδοποίηση — προτάσεις του ίδιου κατηγορήματος μαζί
  5. Προσοχή στο ! — προτίμα πράσινα cuts
  6. Συνείδηση του not — δεν είναι λογικό-όχι, είναι NAF
  7. Αποφυγή assert/retract εκτός εξειδικευμένων περιπτώσεων
  8. Όχι κατάχρηση διάζευξης (;) μέσα σε προτάσεις — προτίμα ξεχωριστές
  9. Ικανοποιητική τεκμηρίωση — τι κάνει κάθε κατηγόρημα
  10. Test-driven — γράφε ερωτήσεις/queries που τεστάρουν κάθε πρόταση

8.4 Όταν δεν Δουλεύει

  • Σταδιακός έλεγχος: από κάτω-προς-τα-πάνω (κάθε υπο-κατηγόρημα) ή από επάνω-προς-τα-κάτω (από το main)
  • Tracing: τα περισσότερα συστήματα Prolog παρέχουν trace/0 ή spy(name/arity)
  • Γραπτή εκτέλεση SLD δέντρου — βοηθάει στο να καταλάβουμε ποια πρόταση επιλέγεται
