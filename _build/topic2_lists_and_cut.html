1. Λίστες: Δομή και Σημειογραφία

Μια λίστα είναι μια διατεταγμένη ακολουθία στοιχείων μεταβλητού μήκους. Στην Prolog δεν υπάρχει «ειδικός τύπος» λίστας — οι λίστες είναι απλώς σύνθετοι όροι που ακολουθούν ένα αναδρομικό ορισμό:

Ορισμός λίστας:
Είτε η κενή λίστα (συμβολίζεται με []),
Είτε ένας σύνθετος όρος με functor την τελεία (.) και δύο ορίσματα: μια κεφαλή (πρώτο στοιχείο) και μια ουρά (μια λίστα).

Δύο Συντακτικοί Τρόποι Γραφής

Η Prolog δίνει δύο ισοδύναμες σημειογραφίες. Η μία αποκαλύπτει τη δομή, η άλλη είναι ευανάγνωστη:

Επίσημη (Dot Functor) Πρακτική (Αγκύλες) Σημασία
[] [] Η κενή λίστα — απλώς ένα άτομο
.(a, []) [a] Λίστα ενός στοιχείου
.(a, .(b, [])) [a, b] Λίστα δύο στοιχείων
.(a, .(b, .(c, []))) [a, b, c] Λίστα τριών στοιχείων
.(Head, Tail) [Head | Tail] Διαχωρισμός κεφαλής/ουράς

Δεντρική Παράσταση

Η λίστα [ann, tom, bob, pat] είναι στην πραγματικότητα ένα δέντρο:

Πολλαπλές Ισοδύναμες Γραφές

Η ευελιξία της σημειογραφίας | επιτρέπει διάφορες ισοδύναμες μορφές της ίδιας λίστας. Όλες οι παρακάτω αναπαριστούν την ίδια λίστα [ann, tom, bob, pat]:

[ann, tom, bob, pat] [ann | [tom, bob, pat]] [ann, tom | [bob, pat]] [ann | [tom | [bob, pat]]] [ann | [tom | [bob | [pat]]]] [ann | [tom | [bob | [pat | []]]]] [ann, tom, bob, pat | []]
🔎 Γιατί τόσοι ισοδύναμοι τρόποι;

Η σημασιολογία του [H | T] είναι «κεφαλή το H, ουρά το T» και το T πρέπει να είναι λίστα. Όταν μέσα στο | έχουμε ξανά λίστα με αγκύλες, ο μεταγλωττιστής τις «ανοίγει» αυτόματα. Έτσι, η Prolog δεν διαχωρίζει αυτές τις γραφές — είναι όλες ο ίδιος όρος στο εσωτερικό.

Παραδείγματα Λιστών με Διαφορετικά Στοιχεία

Τα στοιχεία μιας λίστας μπορούν να είναι οτιδήποτε — άτομα, αριθμοί, μεταβλητές, σύνθετοι όροι, ακόμα και άλλες λίστες:

[a] % ένα στοιχείο [X] % μία ελεύθερη μεταβλητή [X, Y] % δύο μεταβλητές [X | Y] % Head=X, Tail=Y (Y είναι λίστα) [[]] % λίστα με ένα στοιχείο: την κενή λίστα [2, 3 | L] % αρχίζει με 2,3 και συνεχίζει με τη λίστα L [p(1, 3) | R] % Head=ένας σύνθετος όρος [[1, 2], [3, 4, 5], [], [6]] % λίστα από λίστες [A, B | [e, f, g]] % δύο στοιχεία + γνωστή ουρά [q([2, 7]), r([[4]])] % σύνθετα στοιχεία [[a, b] | [c, d]] % Head=[a,b], Tail=[c,d] [_ | _] % οποιαδήποτε μη κενή λίστα
⚠️ Παγίδα: [] vs [[]]

Το [] είναι η κενή λίστα. Το [[]] είναι μια λίστα μήκους 1 που περιέχει την κενή λίστα. Εντελώς διαφορετικά πράγματα! Το πρώτο έχει length 0, το δεύτερο έχει length 1.

2. Βασικές Λειτουργίες στις Λίστες

Όλες οι λειτουργίες σε λίστες της Prolog ακολουθούν ένα συγκεκριμένο μοτίβο: βάση = κενή λίστα ή λίστα ενός στοιχείου · αναδρομικό βήμα = επεξεργασία κεφαλής + αναδρομή στην ουρά. Αν εμπεδώσετε αυτό το μοτίβο, θα μπορείτε να γράφετε νέα κατηγορήματα μόνοι σας.

2.1 Έλεγχος Μέλους: member/2

Το member(X, L) αληθεύει αν το X είναι μέλος της λίστας L. Δύο περιπτώσεις:

  • Το X είναι μέλος αν είναι η κεφαλή της L.
  • Το X είναι μέλος αν είναι μέλος της ουράς της L.
member(X, [X | _]). % βάση: ο X είναι η κεφαλή member(X, [_ | Tail]) :- member(X, Tail). % αναδρομή: ψάξε στην ουρά
Παραδείγματα Εκτέλεσης
?- member(b, [a, b, c]). yes ?- member(b, [a, [b, c]]). no % το b ΔΕΝ είναι μέλος, αλλά το [b,c] είναι ?- member([b, c], [a, [b, c]]). yes ?- member(X, [1, 2, 3]). X = 1 -> ; X = 2 -> ; X = 3 yes % με backtracking παράγει όλα τα μέλη

2.2 Συνένωση: append/3

Το append(L1, L2, L3) αληθεύει όταν η L3 είναι η συνένωση των L1 και L2.

append([], L, L). % βάση: [] ++ L = L append([X | L1], L2, [X | L3]) :- append(L1, L2, L3). % αναδρομή: η κεφαλή «μετακινείται» στην έξοδο
[X | L1]
Πρώτη Λίστα
++
L2
Δεύτερη Λίστα
=
[X | L3]
Αποτέλεσμα
🔄 Αναδρομικό βήμα: Το στοιχείο X της πρώτης λίστας μεταφέρεται απευθείας στην κεφαλή του αποτελέσματος. Καλούμε αναδρομικά το append(L1, L2, L3).

Πολυκατευθυντικότητα του append

Επειδή ο μηχανισμός είναι η ενοποίηση, το append δουλεύει με οποιαδήποτε ορίσματα ελεύθερα. Αυτό είναι μια κλασική αποκάλυψη για όσους έρχονται από διαδικαστικές γλώσσες.

Συνένωση (κλασική χρήση)
?- append([a, b], [c, d, e], L). L = [a, b, c, d, e] yes
Διαχωρισμός: όλες οι πιθανές «κοπές»
?- append(L1, L2, [a, b, c]). L1 = [], L2 = [a, b, c] -> ; L1 = [a], L2 = [b, c] -> ; L1 = [a, b], L2 = [c] -> ; L1 = [a, b, c], L2 = [] yes
Εύρεση «πριν» και «μετά» στόχου

Για να βρω τι έρχεται πριν και μετά τον μήνα Μάιο σε λίστα μηνών:

?- append(Before, [may | After], [jan, feb, mar, apr, may, jun, jul, aug, sep, oct, nov, dec]). Before = [jan, feb, mar, apr] After = [jun, jul, aug, sep, oct, nov, dec] yes

Ή για να βρω γείτονες ενός στοιχείου:

?- append(_, [Month1, may, Month2 | _], [jan, feb, mar, apr, may, jun, jul, aug, sep, oct, nov, dec]). Month1 = apr Month2 = jun yes

Εναλλακτικός ορισμός του member μέσω append

member1(X, L) :- append(_, [X | _], L).

Διαβάζεται: «το X είναι μέλος της L αν υπάρχει διάσπαση της L όπου το X είναι πρώτο στοιχείο του δεξιού μέρους». Λιγότερο αποδοτικό αλλά πολύ κομψό!

2.3 Διαγραφή και Εισαγωγή: del/3, insert/3

% del(X, L, L1): η L1 προκύπτει αν αφαιρέσουμε ΜΙΑ εμφάνιση του X από την L del(X, [X | Tail], Tail). % βάση: το X είναι η κεφαλή del(X, [Y | Tail], [Y | Tail1]) :- del(X, Tail, Tail1). % αναδρομή στην ουρά
% Με backtracking, διαγράφει διαφορετικές εμφανίσεις ?- del(a, [a, b, a, a], L). L = [b, a, a] -> ; L = [a, b, a] -> ; L = [a, b, a] yes % Και ως «διαχωριστής» — βρίσκει όλες τις θέσεις του X ?- del(a, L, [1, 2, 3]). L = [a, 1, 2, 3] -> ; L = [1, a, 2, 3] -> ; L = [1, 2, a, 3] -> ; L = [1, 2, 3, a] yes

Η εισαγωγή ορίζεται κομψά ως η αντίστροφη πράξη της διαγραφής:

insert(X, List, BiggerList) :- del(X, BiggerList, List).

Και ένας άλλος ορισμός του member, μέσω del:

member2(X, List) :- del(X, List, _).

2.4 Προσθήκη στην Αρχή: add/3

add(X, L, [X | L]).

Πραγματικά είναι τόσο απλό: ένα γεγονός! Η ενοποίηση κάνει όλη τη δουλειά.

Άσκηση 2.1 Ορίστε:

  • last(Item, List) ώστε να αληθεύει αν το Item είναι το τελευταίο στοιχείο της List:
    1. μέσω append,
    2. χωρίς append (με ευθεία αναδρομή).
  • Από μια λίστα L, διαγράψτε τα τρία τελευταία στοιχεία (μέσω append).
  • Διαγράψτε τα τρία πρώτα και τα τρία τελευταία στοιχεία της L.
Υποδείξεις
% (1a) μέσω append last(Item, List) :- append(_, [Item], List). % (1b) χωρίς append last(Item, [Item]). last(Item, [_ | Tail]) :- last(Item, Tail). % (2) Διαγραφή 3 τελευταίων drop_last3(L, L1) :- append(L1, [_, _, _], L). % (3) Διαγραφή 3 πρώτων ΚΑΙ 3 τελευταίων drop_3_3(L, L2) :- append([_,_,_], Middle, L), append(L2, [_,_,_], Middle).
🚀

3. Προηγμένη Επεξεργασία: sublist, permutation, reverse

3.1 Υπολίστες (Διαδοχικά Στοιχεία)

Μια υπολίστα είναι μια ακολουθία διαδοχικών στοιχείων μιας λίστας. Π.χ. το [c, d, e] είναι υπολίστα του [a, b, c, d, e, f], αλλά το [c, e] δεν είναι.

sublist(S, L) :- append(L1, L2, L), append(S, L3, L2).
Ολόκληρη Λίστα L
L1 (Πρόθεμα)
S (Υπολίστα)
L3 (Επίθεμα)
L2 = S + L3

Διαβάζεται: «η S είναι υπολίστα της L αν η L μπορεί να σπάσει σε L1 και L2, και η L2 μπορεί να σπάσει σε S και L3». Δηλαδή το S «κάθεται κάπου» μέσα στην L.

?- sublist(S, [a, b, c]). S = [] -> ; S = [a] -> ; S = [a, b] -> ; S = [a, b, c] -> ; S = [] -> ; S = [b] -> ; ...

3.2 Μεταθέσεις (Permutations)

Όλες οι πιθανές διατάξεις των στοιχείων μιας λίστας. Δύο κομψοί ορισμοί:

Με insert
permutation([], []). permutation([X | L], P) :- permutation(L, L1), insert(X, L1, P).
Με del
permutation2([], []). permutation2(L, [X | P]) :- del(X, L, L1), permutation2(L1, P).
?- permutation2([red, blue, green], P). P = [red, blue, green] -> ; P = [red, green, blue] -> ; P = [blue, red, green] -> ; P = [blue, green, red] -> ; P = [green, red, blue] -> ; P = [green, blue, red] yes % 3! = 6 μεταθέσεις

3.3 Αντιστροφή Λίστας: Naive vs Accumulator

Η αντιστροφή είναι το αρχέτυπο για να καταλάβετε γιατί η αναδρομή με συσσωρευτή είναι αποδοτικότερη.

Naive Reverse

reverse([], []). reverse([First | Rest], Reversed) :- reverse(Rest, ReversedRest), append(ReversedRest, [First], Reversed).

Διαβάζεται καλά: «αντιστρέφω την ουρά, μετά κολλάω την κεφαλή στο τέλος». Αλλά: κάθε append(ReversedRest, [First], _) κοστίζει O(N) γιατί διασχίζει το ReversedRest. Άρα συνολικά O(N²).

Accumulator Reverse (O(N))

reverse1(List1, List2) :- rev_app(List1, [], List2). rev_app([], Acc, Acc). rev_app([X | List1], Acc, Result) :- rev_app(List1, [X | Acc], Result).

Πώς δουλεύει; Φανταστείτε ότι ξεφορτώνετε στοιχεία από μια στοίβα και τα τοποθετείτε σε άλλη στοίβα — η σειρά αντιστρέφεται φυσικά:

🔄 Βήμα-Προς-Βήμα Tracing Αντιστροφής με Συσσωρευτή (Accumulator)
Βήμα 1 List = [a, b, c, d]
➔
Acc = []
Βήμα 2 List = [b, c, d]
➔
Acc = [a]
Βήμα 3 List = [c, d]
➔
Acc = [b, a]
Βήμα 4 List = [d]
➔
Acc = [c, b, a]
Τέλος List = []
➔
Result = [d, c, b, a]
🔎 Γιατί O(N) αντί για O(N²);

Στο naive, σε κάθε επίπεδο αναδρομής το append διασχίζει όλο τον ήδη-αντεστραμμένο πίνακα. Έτσι: 1ο βήμα διασχίζει 0 στοιχεία, 2ο βήμα 1, ..., Νο βήμα N-1. Σύνολο: 0+1+...+N-1 = N(N-1)/2 = O(N²).

Στο accumulator, σε κάθε βήμα κάνουμε μόνο [X | Acc] — προσθήκη στην αρχή, O(1). Επί N βήματα = O(N).

Trade-off: η accumulator έκδοση είναι λιγότερο «δηλωτική» (απαιτεί τρίτο όρισμα) αλλά πολύ αποδοτικότερη — και πιο φιλική στη tail recursion.

3.4 Μέσο (translate) μέσω αναδρομής

Παράδειγμα μετάφρασης ψηφίων σε αγγλικές λέξεις:

means(0, zero). means(1, one). means(2, two). means(3, three). means(4, four). means(5, five). means(6, six). means(7, seven). means(8, eight). means(9, nine). translate([], []). translate([X | L1], [Y | L2]) :- means(X, Y), translate(L1, L2). ?- translate([3, 5, 1, 3], List). List = [three, five, one, three] yes

Άσκηση 2.2 Ορίστε τα παρακάτω. Όλα μέσω αναδρομής και χωρίς ενσωματωμένα κατηγορήματα:

  1. evenlength(List), oddlength(List): αληθεύουν αν η L έχει άρτιο/περιττό μήκος.
  2. palindrome(List): αληθεύει αν η λίστα είναι ίδια διαβαζόμενη ανάποδα.
  3. shift(List1, List2): παίρνει την πρώτη και τη βάζει τελευταία. Π.χ. shift([1,2,3,4,5], L1) δίνει L1 = [2,3,4,5,1].
  4. subset(Set, SubSet): παράγει όλα τα υποσύνολα της Set (όχι μόνο υπολίστες).
  5. dividelist(List, List1, List2): χωρίζει εναλλάξ τα στοιχεία της L σε δύο λίστες.
  6. flatten(List, FlatList): «ισιώνει» μια εμφωλιασμένη λίστα. Π.χ. [a, b, [c, d], [], [[e]], f] → [a, b, c, d, e, f].

4. Λίστες Διαφορών (Difference Lists)

Μια κλασική τεχνική για να γράφουμε αποδοτικότερη Prolog. Η μέθοδος βασίζεται σε μια έξυπνη παρατήρηση: αντί να μεταβιβάζουμε μια λίστα L, μεταβιβάζουμε ένα ζευγάρι λιστών L1-L2 όπου η "πραγματική" λίστα είναι η διαφορά τους.

4.1 Η Ιδέα

Η λίστα [a, b, c] μπορεί να αναπαρασταθεί ως "ό,τι λείπει" με πολλούς τρόπους:

[a, b, c] ≡ [a, b, c] − []
[a, b, c] ≡ [a, b, c, d, e] − [d, e]
[a, b, c] ≡ [a, b, c, d, e | T] − [d, e | T]
[a, b, c] ≡ [a, b, c | T] − T

Αυτή η τελευταία μορφή είναι κρίσιμη: [a, b, c | T] − T. Η Prolog το γράφει ως [a,b,c|T]-T.

4.2 Το Τέχνασμα: append σε O(1)!

Με λίστες διαφορών, η συνένωση γίνεται χωρίς αναδρομή — απλά ενοποίηση μεταβλητών:

new_append(A1-Z1, Z1-Z2, A1-Z2).
new_append(A1-Z1, ...)
Πρώτη λίστα: A1-Z1 (από A1 ξεκινάει, μέχρι Z1 πάει).
..., Z1-Z2, ...
Δεύτερη λίστα: η ουρά της πρώτης (Z1) ενοποιείται με την αρχή της δεύτερης. Έτσι "συγκολλώνται"!
..., A1-Z2)
Αποτέλεσμα: από την αρχή της πρώτης (A1) μέχρι το τέλος της δεύτερης (Z2).
?- new_append([a,b,c|T1]-T1, [d,e|T2]-T2, L). T1 = [d, e | _0084] T2 = _0084 L = [a, b, c, d, e | _0084] - _0084
💡 Γιατί O(1);

Το παραδοσιακό append έχει πολυπλοκότητα O(n) γιατί πρέπει να "διασχίσει" όλη την πρώτη λίστα. Με λίστες διαφορών, η συγκόλληση γίνεται με μία απλή ενοποίηση μεταβλητής (Z1 με Z2) — άρα O(1)!

4.3 Παράδειγμα Εφαρμογής: add_at_end

Πώς προσθέτουμε στο τέλος μιας λίστας; Με κανονικές λίστες χρειάζεται O(n). Με διαφορών:

add_at_end(L-[Item|Z], Item, L-Z).

Πάλι O(1)! Η ουρά Z της λίστας διαφορών "ενοιγμένη" αντικαθίσταται με την κενή Z μετά το Item.

4.4 Αποδοτική Αντιστροφή Λίστας με Λίστες Διαφορών

Στην ενότητα §3 είδαμε ότι η αναδρομική reverse/2 έχει πολυπλοκότητα O(n²). Με λίστες διαφορών μπορούμε να φτιάξουμε O(n):

reverse_dl(List, Reversed) :- reverse_dl(List, Reversed-[]). reverse_dl([], Z-Z). reverse_dl([H|T], R-Z) :- reverse_dl(T, R-[H|Z]).

4.5 Πότε Χρησιμοποιούμε Λίστες Διαφορών;

  • Όταν χρειάζεται συχνή συνένωση/προσθήκη στο τέλος
  • Σε quicksort για O(n log n) πραγματικό
  • Σε DCG (Definite Clause Grammars) για NL parsing — η Prolog τις χρησιμοποιεί αυτόματα
  • Σε συντακτικούς αναλυτές γενικότερα
⚠️ Δυσκολία Ανάγνωσης

Ο κώδικας με λίστες διαφορών είναι δυσανάγνωστος για αρχάριους. Συνιστάται να γράφεις πρώτα την έκδοση με κανονικές λίστες, και μετά να μετατρέπεις σε λίστες διαφορών αν χρειάζεται αποδοτικότητα.

4.6 Εναλλακτικές Αναπαραστάσεις Λιστών

Η Prolog δεν μας δεσμεύει στο σύμβολο [...] για λίστες. Μπορούμε να ορίσουμε δικό μας:

:- op(500, xfy, then). % Η λίστα enter, sit, eat γράφεται: % enter then sit then eat then donothing appendl(donothing, L, L). appendl(X then L1, L2, X then L3) :- appendl(L1, L2, L3).

Όπου donothing παίζει το ρόλο της κενής λίστας [], και then τον ρόλο του |.

💡 Άσκηση Εξετάσεων

Συνηθισμένη άσκηση: να γραφεί convert/2 που μετατρέπει από [a, b, c] σε a then b then c then donothing. Λύση:

convert([], donothing). convert([X|Xs], X then Rest) :- convert(Xs, Rest).
➕

5. Τελεστές (Operators)

Όταν γράφετε 2 * a + b * c, βλέπετε μια αριθμητική έκφραση. Όταν η Prolog την βλέπει, βλέπει τον σύνθετο όρο +(*(2, a), *(b, c)). Οι τελεστές είναι απλώς συντακτική ζάχαρη: σας επιτρέπουν να γράφετε γνώριμες εκφράσεις, αλλά κάτω από το καπό η Prolog εξακολουθεί να βλέπει σύνθετους όρους.

Ορισμός Τελεστών

Ορίζονται με την οδηγία:

:- op(Precedence, Type, Name).
  • Precedence: Ακέραιος από 0 έως 1200. Μεγαλύτερη τιμή = «πιο έξω» στο δέντρο, χαμηλότερη ισχύς σύνδεσης.
  • Type: Ένα από τα xfx, xfy, yfx, fx, fy, xf, yf (εξηγούνται παρακάτω).
  • Name: Το όνομα του τελεστή (άτομο).

Είδη Τελεστών

Το όνομα του τύπου κωδικοποιεί τη θέση του τελεστή σχετικά με τα ορίσματα και την προσεταιριστικότητα. Η f δηλώνει τη θέση του τελεστή· τα x, y δηλώνουν τις θέσεις των ορισμάτων και ποια προτεραιότητα επιτρέπουν.

ΤύποςΘέσηΠροσεταιριστικότηταΠαράδειγμα
xfxInfixΜη προσεταιριστικός:-, =, is
yfxInfixΑριστερά προσεταιριστικός+, -
xfyInfixΔεξιά προσεταιριστικός,, ;
fxPrefixΧωρίς επανάληψη:- (ως οδηγία)
fyPrefixΜε επανάληψηnot, - (πρόσημο)

yfPostfixΜε επανάληψησπάνιο
🔎 Τι ακριβώς σημαίνει x και y;

Σε ένα ορισμό op(P, ?f?, _):

  • Η θέση που σημαδεύεται με x δέχεται όρισμα με προτεραιότητα αυστηρά μικρότερη του P.
  • Η θέση που σημαδεύεται με y δέχεται όρισμα με προτεραιότητα μικρότερη ή ίση του P.

Πρακτικά, αυτό καθορίζει την προσεταιριστικότητα. Επειδή το - είναι yfx (αριστερό όρισμα ίδιας προτεραιότητας επιτρέπεται), το a - b - c διαβάζεται ως (a-b)-c. Αντίθετα, αν ήταν xfy, θα διαβαζόταν ως a-(b-c)!

Παράδειγμα Δικού μας Τελεστή

:- op(600, xfx, has). has(peter, information). % κανονική κλήση peter has information. % συντακτικά ισοδύναμη χρήση :- op(650, xfx, supports). floor supports table.

Παρά την ονομασία τους («τελεστές»), δεν τελούν τίποτα στα ορίσματά τους. Είναι μόνο συντακτική ζάχαρη. Το 1+2 ΔΕΝ είναι ο αριθμός 3 — είναι ο όρος +(1,2). Αν θέλετε υπολογισμό, χρειάζεστε τον τελεστή is (επόμενη ενότητα).

Άσκηση 2.3 Με τους τελεστές:

:- op(300, xfx, plays). :- op(200, xfy, and).

Σε ποιους όρους «μεταφράζονται» οι παρακάτω;

  • jimmy plays football and squash
  • susan plays tennis and basketball and volleyball
Λύση

jimmy plays football and squash → plays(jimmy, and(football, squash))

susan plays tennis and basketball and volleyball → plays(susan, and(tennis, and(basketball, volleyball))) (γιατί and είναι xfy, δηλαδή δεξιά προσεταιριστικός)

6. Αριθμητική και Αξιολόγηση

Στην Prolog υπάρχει μια θεμελιώδης διάκριση που ταράζει αρχάριους:

  • Το = είναι ενοποίηση — δεν υπολογίζει τίποτα.
  • Το is είναι αριθμητική αξιολόγηση — υπολογίζει και αναθέτει.
?- X = 1 + 2. X = 1 + 2 % Η X πήρε τον όρο +(1,2) yes ?- X is 1 + 2. X = 3 % Η X πήρε τον αριθμό 3 yes

Αριθμητικοί Τελεστές

Αξιολογούνται όταν εμφανίζονται στο δεξί μέλος του is (ή σε αριθμητική σύγκριση): +, -, *, /, // (ακέραιη διαίρεση), mod.

Τελεστές Σύγκρισης

Αξιολογούν και τα δύο μέλη πριν συγκρίνουν:

  • X < Y · X > Y · X =< Y · X >= Y
  • X =:= Y: «αριθμητικά ίσα» (μετά αξιολόγηση)
  • X =\= Y: «αριθμητικά διαφορετικά»
?- 12 * 7 > 50. yes ?- 1 + 2 =:= 2 + 1. yes % αριθμητική σύγκριση ?- 1 + 2 = 2 + 1. no % συντακτική σύγκριση — δομές διαφορετικές ?- 1 + A = B + 2. A = 2, B = 1, yes % ενοποίηση δομών
⚠️ Το is Απαιτεί Πλήρως Αποτιμημένο Δεξί Μέλος

Το X is Y + 1 θα αποτύχει αν η Y δεν έχει πάρει αριθμητική τιμή ήδη. Δεν είναι σαν εξίσωση που λύνεται· είναι αλγόριθμος που υπολογίζει.

?- X is Y + 1. ERROR: Arguments are not sufficiently instantiated

Παράδειγμα: Μήκος Λίστας (Τρεις Εκδόσεις)

% Έκδοση 1: Απλή αναδρομή length([], 0). length([_ | Tail], N) :- length(Tail, N1), N is 1 + N1. ?- length([a, b, [c, d], e], N). N = 4 yes
% Έκδοση 2: Με accumulator (tail recursive) length1(List, N) :- length2(List, 0, N). length2([], N, N). length2([_ | Tail], N1, N) :- N2 is 1 + N1, length2(Tail, N2, N).
🔎 Έκδοση 3: «Άπληστη» έκφραση μήκους

Αν παραλείψουμε εντελώς το is, παίρνουμε μια αριθμητική έκφραση αντί για αριθμό:

length3([], 0). length3([_ | Tail], 1 + N) :- length3(Tail, N). ?- length3([a, b, c], N). N = 1 + (1 + (1 + 0)) % δομή, όχι αριθμός yes ?- length3([a, b, c], N), Length is N. Length = 3 % τώρα υπολογίζεται

Παράδειγμα: ΜΚΔ (gcd)

gcd(X, X, X). gcd(X, Y, D) :- X < Y, Y1 is Y - X, gcd(X, Y1, D). gcd(X, Y, D) :- Y < X, gcd(Y, X, D). ?- gcd(20, 25, D). D = 5 yes

Άσκηση 2.4 Ορίστε:

  1. max(X, Y, Max): ο Max είναι ο μεγαλύτερος.
  2. maxlist(List, Max): το μέγιστο στοιχείο μιας λίστας.
  3. sumlist(List, Sum): άθροισμα μιας λίστας αριθμών.
  4. ordered(List): αληθεύει αν η λίστα είναι ταξινομημένη σε αύξουσα σειρά.
  5. between(N1, N2, X): παράγει με backtracking όλες τις τιμές X από N1 έως N2.
  6. subsum(Set, Sum, SubSet): επιστρέφει όλα τα υποσύνολα της Set με δοσμένο άθροισμα.
⚖️

7. Είδη Ισότητας στην Prolog

Η Prolog έχει τέσσερα διαφορετικά είδη «ισότητας». Αυτό μπερδεύει τους αρχάριους, αλλά καθένα έχει διακριτό ρόλο.

ΤελεστήςΕίδοςΠαράδειγμα
X = Y «Ισότητα» ενοποίησης f(a, b) = f(a, X) → X=b · 1+2 = 2+1 → no
X \= Y Δεν ενοποιούνται f(a) \= g(b) → yes
X is E «Ισότητα» αξιολόγησης αριθμητικής X is 1+2 → X=3
E1 =:= E2 Αριθμητικά ίσες τιμές 1+2 =:= 2+1 → yes
T1 == T2 «Ισότητα» κατά λέξη (συντακτική ταυτότητα) f(a,X) == f(a,X) → yes · f(a,X) == f(a,Y) → no
T1 \== T2 Διαφορετικοί όροι κατά λέξη X \== Y → yes (αν είναι διαφορετικές μεταβλητές)
Διακριτικά Παραδείγματα
?- f(a, b) == f(a, b). yes ?- f(a, X) == f(a, Y). no % X και Y είναι διαφορετικές μεταβλητές ?- f(a, X) == f(a, X). yes % ίδια μεταβλητή X ?- t(X, f(a, Y)) == t(X, f(a, Y)). yes

Διαφορά κρίσιμη: το == ελέγχει αν δύο όροι είναι συντακτικά ταυτόσημοι ως έχουν τώρα, χωρίς να κάνει ενοποίηση. Άρα δύο ξεχωριστές ελεύθερες μεταβλητές X και Y δεν είναι ίδιες με ==, παρόλο που = θα τις ενοποιούσε.

🔎 Παράδειγμα: count (πόσες φορές εμφανίζεται όρος;)

Το == είναι χρήσιμο όταν θέλουμε αυστηρή σύγκριση χωρίς παρενέργειες ενοποίησης:

count(_, [], 0). count(Term, [Head | Tail], N) :- Term == Head, !, count(Term, Tail, N1), N is N1 + 1 ; count(Term, Tail, N). ?- count(a, [a, b, X, a], N). X = _0090, N = 2 yes % Δεν ενοποιεί το X με a — επειδή χρησιμοποιούμε ==

8. Διαδικαστική Σημασία & Μηχανισμός Εκτέλεσης

Ας θυμηθούμε σε λίγο μεγαλύτερη ακρίβεια τον αλγόριθμο εκτέλεσης. Δεδομένης λίστας στόχων G1, G2, ..., Gm:

  1. Εύρεση πρώτης πρότασης C : H :- B1, ..., Bn με την κεφαλή H να ενοποιείται με τον G1.
  2. Χρήση παραλλαγής C' με «φρέσκα» ονόματα μεταβλητών (δεν χρησιμοποιεί τα ίδια ονόματα με τα G1, ..., Gm).
  3. Αντικατάσταση του G1 με B1', ..., Bn' και εφαρμογή των αποτιμήσεων που προέκυψαν από την ενοποίηση.
  4. Αν δεν βρεθεί πρόταση, οπισθοδρόμηση στην τελευταία επιλογή.
  5. Όταν εξαντληθεί η λίστα στόχων → επιτυχία.

Ατέρμονες Ανακυκλώσεις

Δύο κλασικά παραδείγματα που φέρνουν την Prolog σε αδιέξοδο:

% 1. Αυτοαναφορά p :- p. ?- p. % Stack overflow — άπειρη αναδρομή % 2. Πίθηκος και μπανάνα με λάθος σειρά: % Σειρά grasp, climb, push, walk → η Prolog εγκλωβίζεται σε walk-walk-walk-...

Συμπέρασμα

⚖️ Δύο Σημασίες, Μια Γλώσσα

«Ένα πρόγραμμα Prolog δηλωτικά σωστό μπορεί να είναι διαδικαστικά λάθος.»

Είναι ευθύνη του προγραμματιστή να εξασφαλίσει και τις δύο διαστάσεις. Η μεθοδολογία της σταδιακής εκλέπτυνσης (stepwise refinement) και η χρήση αναδρομής είναι τα βασικά εργαλεία ανάπτυξης.

✂️

9. Ο Τελεστής Cut (!)

🚨 Τι Κάνει το Cut

Το ! είναι ένας side-effect τελεστής. Πετυχαίνει πάντα την πρώτη φορά που εκτελείται, ΑΛΛΑ δεσμεύει την Prolog: μετά το !, η Prolog ΔΕΝ μπορεί να κάνει backtracking πέρα από το σημείο εκείνο. Συγκεκριμένα:

  • Αγνοούνται τυχόν εναλλακτικοί τρόποι ικανοποίησης των στόχων αριστερά του ! μέσα στο τρέχον σώμα κανόνα.
  • Αγνοούνται τυχόν άλλες προτάσεις για το ίδιο κατηγόρημα.
  • Η οπισθοδρόμηση επιτρέπεται μόνο στους στόχους δεξιά του !.

Παράδειγμα Κίνητρου: Έλεγχος Backtracking

Έστω η συνάρτηση:

f(X, 0) :- X < 3. f(X, 2) :- 3 =< X, X < 6. f(X, 4) :- 6 =< X.

Σκεφτείτε γραφικά:

Y
4 ........ ←─────
2 .... ←────
0 ←─
  0   3    6   X

Για το ερώτημα ?- f(1, Y), 2 < Y.:

  1. Η Prolog δοκιμάζει την 1η πρόταση: X=1 < 3 ✓, άρα Y=0.
  2. Στόχος 2 < 0: αποτυχία.
  3. Backtrack στην 1η πρόταση: δεν έχει άλλες επιλογές.
  4. Δοκιμάζει 2η: 3 =< 1 αποτυχία.
  5. Δοκιμάζει 3η: 6 =< 1 αποτυχία.
  6. Συνολικό fail.

Η Prolog περιττά δοκίμασε την 2η και 3η πρόταση παρόλο που είναι αδύνατο να αληθεύουν αφού η X=1 ικανοποιεί το X<3. Με το ! μπορούμε να της πούμε «μόλις πετύχει η πρώτη συνθήκη, μη ξαναδοκιμάσεις τις άλλες».

2ος Ορισμός: Με Πράσινα Cuts (Green Cuts)

f(X, 0) :- X < 3, !. f(X, 2) :- 3 =< X, X < 6, !. f(X, 4) :- 6 =< X.

Εδώ τα ! λένε: «Αν η συνθήκη της 1ης πρότασης πέρασε, μην κοιτάς πλέον άλλες προτάσεις». Η δηλωτική σημασία διατηρείται! Το πρόγραμμα γίνεται ταχύτερο χωρίς αλλαγή νοήματος. Αυτά λέγονται πράσινα cuts.

3ος Ορισμός: Με Κόκκινα Cuts (Red Cuts)

f(X, 0) :- X < 3, !. f(X, 2) :- X < 6, !. % παραλείπει την κάτω συνθήκη 3 =< X f(X, 4). % χωρίς συνθήκη!

Εδώ τα ! είναι απαραίτητα για την ορθότητα. Αν τα αφαιρέσουμε, το πρόγραμμα δίνει λάθος αποτελέσματα: π.χ. το f(1, 2) θα γίνει αληθές γιατί 1 < 6!

Είδος CutΕπίδραση στη Δηλωτική ΣημασίαΑσφάλεια
Πράσινο (Green) Δεν αλλάζει — μόνο επιτάχυνση Ακίνδυνο, μπορεί να αφαιρεθεί
Κόκκινο (Red) Αλλάζει — το πρόγραμμα δουλεύει μόνο με αυτό Επικίνδυνο, χρειάζεται προσοχή

Επίσημη Συμπεριφορά του Cut

Για τον κανόνα:

C :- P, Q, R, !, S, T, U. C :- V. A :- B, C, D. ?- A.

Όταν εκτελείται ο C και περάσει το !:

  • Αγνοούνται τυχόν εναλλακτικοί τρόποι για τα P, Q, R.
  • Αγνοείται η δεύτερη πρόταση C :- V.
  • Backtracking επιτρέπεται μόνο μεταξύ των S, T, U.
  • Σε επόμενες αποτυχίες, backtracking μπορεί να γίνει στο B (επιστρέφοντας έξω από το C).

Κλασικά Παραδείγματα Χρήσης

Παράδειγμα 1: Maximum δύο αριθμών
% Χωρίς cut: σαφές, δηλωτικό, αλλά κάνει περιττό έλεγχο max(X, Y, X) :- X >= Y. max(X, Y, Y) :- X < Y. % Με cut (πράσινο, καλύτερο) max(X, Y, X) :- X >= Y, !. max(_, Y, Y).
Παράδειγμα 2: Member ντετερμινιστικός (μόνο 1η εμφάνιση)
member(X, [X | _]) :- !. member(X, [_ | L]) :- member(X, L). ?- member(f(Z), [g(a), f(b), g(c), f(d)]). Z = b % χωρίς cut θα έδινε και το Z=d με backtracking yes
Παράδειγμα 3: Προσθήκη χωρίς διπλοτυπία
add(X, L, L) :- member(X, L), !. add(X, L, [X | L]). ?- add(a, [b, c], L). L = [a, b, c] % δεν υπήρχε — προστέθηκε ?- add(b, [a, b, c], L). L = [a, b, c] % υπήρχε — αμετάβλητη
Παράδειγμα 4: Class — κλασικό σφάλμα με cut
beat(tom, jim). beat(ann, tom). beat(pat, jim). % Κατάταξη παικτών class(X, fighter) :- beat(X, _), beat(_, X), !. class(X, winner) :- beat(X, _), !. class(X, sportsman) :- beat(_, X). ?- class(tom, C). C = fighter, yes ?- class(jim, C). C = sportsman, yes ?- class(tom, sportsman). yes !!! Λάθος !!!

Το τελευταίο είναι θεωρητικά λάθος: ο tom είναι fighter, όχι sportsman. Συμβαίνει γιατί η Prolog με το ορισμένο όρισμα sportsman πηγαίνει κατευθείαν στην 3η πρόταση, παρακάμπτοντας τα προηγούμενα cuts. Συμπέρασμα: τα προγράμματα με cut συχνά «προϋποθέτουν» συγκεκριμένο τρόπο κλήσης (π.χ. class(<Atom>, <Variable>)).

10. Άρνηση ως Αποτυχία

Η Prolog δεν διαθέτει «πραγματική» λογική άρνηση. Αντί αυτής, έχει την άρνηση ως αποτυχία (Negation as Failure, NAF): αν ο στόχος G δεν μπορεί να αποδειχθεί, τότε not G πετυχαίνει.

Ορισμός του not μέσω cut + fail

not(Goal) :- call(Goal), !, fail. not(_).

Διαβάζεται: «Δοκίμασε να αποδείξεις τον Goal. Αν τα καταφέρεις, σταμάτησε (!) και αποτύχησε (fail). Αν δεν τα καταφέρεις, η 2η πρόταση πετυχαίνει πάντα.»

Συντακτικά, μπορούμε να γράψουμε \+ Goal ή not Goal (αν είναι ορισμένος ως prefix τελεστής).

Παραδείγματα Εφαρμογής

«Διαφορά»
% Έκδοση χωρίς not different(X, X) :- !, fail. different(_, _). % Έκδοση με not — πιο διαβαστή different(X, Y) :- not (X = Y).
«Αρέσει η Μαίρη — αλλά όχι τα φίδια»
% Πρώτη έκδοση: με !, fail likes(mary, X) :- snake(X), !, fail. likes(mary, X) :- animal(X). % Πιο κομψά, με not likes(mary, X) :- animal(X), not snake(X).

Παραδοχή Κλειστού Κόσμου (Closed World Assumption — CWA)

🌍 Τι σημαίνει «Κλειστός Κόσμος»

Η NAF στηρίζεται στην παραδοχή ότι όσα δεν αποδεικνύονται από το πρόγραμμα είναι ψευδή. Αυτό λέγεται Closed World Assumption. Σε αντίθεση με την Open World Assumption του Σημαντικού Ιστού (που θα δούμε στο Κεφάλαιο 6), όπου το «δεν αποδείχθηκε» δεν συνεπάγεται «ψευδές».

Πρακτικά: αν δεν δηλώνεις ότι η liz είναι γονέας της pat, η Prolog θα απαντήσει no στο ?- parent(liz, pat). — όχι «δεν ξέρω».

Παγίδες του NAF

⚠️ Παράδειγμα: Διαφορετική σειρά στόχων → διαφορετικό αποτέλεσμα
good_standard(jeanluis). expensive(jeanluis). good_standard(francesco). reasonable(Restaurant) :- not expensive(Restaurant). ?- good_standard(X), reasonable(X). X = francesco, yes ?- reasonable(X), good_standard(X). no !!! Αναπάντεχα !!!

Στο δεύτερο ερώτημα, το reasonable(X) καλείται με ελεύθερη X. Η Prolog ψάχνει «κάποιο X που δεν είναι expensive». Επειδή το X είναι ελεύθερο και υπάρχει expensive(jeanluis), το πρόγραμμα αποτυγχάνει — αντί να επιστρέψει «αλλά υπάρχουν άλλα X που δεν είναι expensive»!

Συμπέρασμα: Το not δεν συμπεριφέρεται «λογικά» όταν εφαρμόζεται σε στόχους με ελεύθερες μεταβλητές. Είναι ασφαλέστερο να καλούμε not σε πλήρως αποτιμημένους στόχους.

💡 Συμπεράσματα Κεφαλαίου
  • Λίστες: [H|T] + αναδρομή = όλα τα κλασικά κατηγορήματα (member, append, del, …).
  • Accumulators: Tail recursion, O(N) αντί O(N²).
  • Τελεστές: Συντακτική ζάχαρη — δεν υπολογίζουν.
  • Αριθμητική: Το is για υπολογισμό, το =:= για αριθμητική σύγκριση.
  • Cut (!): Ελέγχει το backtracking. Πράσινα = επιτάχυνση. Κόκκινα = αλλαγή σημασίας.
  • Άρνηση ως Αποτυχία: Όχι λογική άρνηση — προσοχή με ελεύθερες μεταβλητές.

Άσκηση 2.5 Ορίστε:

  1. Σε Prolog την ερώτηση: «Ποια στοιχεία της λίστας Candidates δεν ανήκουν στη λίστα RuledOut;» — μέσω backtracking.
  2. difference(Set1, Set2, SetDifference): ?- difference([a,b,c,d], [b,d,e,f], D). → D = [a,c].
  3. class(Number, Class) με χρήση !: positive αν N>0, zero αν N=0, negative αν N<0.
  4. split(Numbers, Positives, Negatives): δύο εκδόσεις (με και χωρίς !).
